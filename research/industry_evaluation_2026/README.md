# Industry evaluation practice, October 2026

Research run of 2026-10-20. Four Opus researchers each covered one layer of
how the industry evaluates LLMs and agents; a fifth wrote the report.
Companion to `../agent_as_a_judge/`, which covers the academic literature.

| Path | What it is |
|---|---|
| `report.md` | The synthesis across the four layers, cross-cutting trends, and where an agent-that-judges-agents fits. Start here. |
| `research_notes/` | One summary per layer, with URLs inline. |
| `notes/` | One note per source, ~130 files, named `<YYYY-MM> <org> <short title>.md`. Frontmatter has `url`, `kind` and `category`. `_TEMPLATE.md` is the shape. |

Categories in `notes/`:

| `category` | Layer |
|---|---|
| `frontier-labs` | System cards, lab eval frameworks, graders, eval awareness, third-party testing |
| `eval-tooling` | Observability and eval platforms, cloud eval services, open-source frameworks, simulation and red-team tools, tracing standards |
| `third-party-and-benchmarks` | Independent evaluators, benchmark audits and saturation, arenas, regulation and codes of practice |
| `production-practice` | Practitioner playbooks, company eval stacks, judge validation, agent evals in production, failure stories |

Figures marked "secondary", "unverified", "marketing" or "recalled" in a note
