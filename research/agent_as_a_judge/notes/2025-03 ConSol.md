# ConSol: Sequential Probability Ratio Testing to Find Consistent LLM Reasoning Paths Efficiently

## One line
Replaces fixed 40-sample self-consistency voting with Wald's sequential probability ratio test, which stops sampling once one answer is significantly ahead of the runner-up, cutting tokens by 64-89% at roughly the same accuracy.

## Method
Problem: self-consistency takes the majority answer over a fixed 40 or 64 reasoning samples, multiplying cost 40-64x, even when the first few samples already agree. The prior early-stopping method, Adaptive-Consistency, checks a Beta/Dirichlet posterior after every sample, which the authors argue inflates the Type I error rate through repeated "peeking", so it may stop on an answer that is not really dominant.

Idea:
- Treat each final answer as an i.i.d. draw from a categorical distribution; the vote picks its mode.
- Reduce to the two most frequent answers: p' = p_first / (p_first + p_second). "No dominant answer" is H0: p' = 0.5; "one answer dominates" is H1: p' > 0.5. This is a Bernoulli test on the top-two counts.
- Run it as an SPRT: multiply the likelihood ratio sample by sample, stop and return the leader when it crosses A = (1-β)/α, stop and give up when it falls below B = β/(1-α), otherwise keep sampling. SPRT is chosen because, under i.i.d. draws, it needs the fewest samples on average of any test with the same error rates, and it controls Type I error under continuous monitoring. A mixture variant (mSPRT) averages the alternative over a Beta prior truncated to (0.5, 1] instead of fixing one value.
- Two calibrations away from clinical-trial defaults. (1) Sensitivity: H1 is set to p' = 0.5001 (standard is 0.55-0.6), and the mSPRT prior is a sharp bell around 0.5, so tiny leads count. (2) β ≈ 1 − α, an extreme tolerance for Type II error: the test may quit early on weak evidence that nothing dominates. The reason given is Figure 2: when the top answer has under half the probability mass, neither of the top two is usually correct, so more samples buy little.
- Engineering: before each round it computes how many samples are needed in the best case to stop and requests them in parallel, usually two or three per round.

## Evaluated on
- Large token savings over Self-Cons@40: SPRT cuts tokens by 63.9-88.6% and mSPRT by 57.3-88.7% across AIME24 (o3-mini low/medium/high), GPQA Diamond and GSM8K, against 47.9-82.8% for Adaptive-Consistency and 49.3-79.2% for the naive p-value baseline.
- Accuracy about the same: within about one point of Self-Cons@40 in most cells (e.g. GSM8K 94.2% vs 93.5% SPRT, 93.9% mSPRT). The one gain, AIME24 o3-mini-low 70.0% to 80.0%, is put down to SPRT being allowed up to 256 samples on hard, inconsistent questions.
- In a simulation sampled from fitted answer distributions, mSPRT finds the mode with fewer average samples than Self-Consistency or Adaptive-Consistency, and passes the consistency ceiling that a fixed 40 samples can reach.

## Limitations admitted by the authors
- Sensitive to parameters. The β sweep in Figure 3 spans only 0.94979 to 0.94997, so the operating point hangs on the fourth decimal. They name systematic calibration as future work.
- Only short-answer and multiple-choice tasks, where answers can be matched exactly. Free-form or consensus-style outputs, which judges usually produce, are untested.
- Clinical-trial guarantees are traded away on purpose. The calibrated settings drop the standard Type II control because the standard settings "require sample sizes that exceed practical limits".

## What it leaves untried
- Free-form or rubric judgments. Clustering semantically equal answers before the test would show whether the token savings survive outside exact-match tasks, which is where LLM judges sit.
- Checking the error-control claim. The paper's case against Adaptive-Consistency is inflated Type I error, but no false-stop rate is measured for either method; the evidence is accuracy and token counts only. Also, with β ≈ 1 − α the paper's own threshold formulas put A and B both close to 1, so the guarantee is nearly empty, and an empirical false-stop rate would show what is actually controlled.
- Correlated samples. The test assumes i.i.d. draws, but repeated samples from one model on one prompt share its errors, so a confident wrong mode stops just as fast as a right one. Nothing in the paper addresses that case.
