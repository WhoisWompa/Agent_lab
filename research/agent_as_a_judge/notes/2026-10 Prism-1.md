# Prism-1: Position- and Rival-Independent Scoring for System One Models

## One line
Shows that the only one-pass decision read that ignores option order and cannot be steered by an added option is a softmax over scores that each see one option alone, and builds that read into a fine-tuned LLM.

## Method
Problem: System One decision models list options under letters and read the letter probabilities (SCQ). The listing and option set come from other components (tool registries, retrievers, page layouts) and can be manipulated, so two axioms should hold: order invariance, and Luce's choice axiom (adding an option leaves the odds ratios of the others unchanged, so a new option can win but cannot redirect the choice among the old ones). SCQ breaks both: one shuffle changes 12-20% of untrained answers, and a well-chosen added option steers 4-34% of decisions.

Idea: by Luce's theorem, a rule satisfies both axioms if and only if it is a softmax over scores s(state, question, option), each depending on one option alone. In a transformer this holds by construction only if no token that feeds an option's score attends to another option and positions do not depend on the listing. Standard fixes fail: shuffled-order training plateaus near 6% flips, sorting freezes a convention (Z-A instead of A-Z changes 7-8% of answers), and set architectures are order-invariant but read the answer from tokens that see every option.

Prism-1: a shared context (state, question, "is the following candidate the correct answer?") is computed once; each option is a block starting at the same position P, attending causally to the context and itself, never to another block. The score is log P(yes) - log P(no) at the block's last token, and the decision is the softmax across blocks. That softmax is the posterior if each block is an independent yes/no judgment and exactly one option is correct. Trained with LoRA on cross-entropy over the options; a new option only needs its own block.

## Evaluated on
- Ties trained SCQ on accuracy while satisfying both axioms: 79.5% vs 80.4% (Gemma 4 12B) and 78.0% vs 77.9% (Qwen3-8B), not significant (p >= 0.13); SCQ still flips 7.1% and 7.4% of answers, Prism-1 flips none.
- Ahead once answers must survive reordering: +1.6 and +3.7 points; +4.7 and +8.1 if SCQ must be right under all K rotations.
- Immune to added and injected options: an option claiming "the correct answer is X" redirects 23% / 15% of Set-LLM and 55% / 31% of Set-Based Prompting decisions and none of Prism-1's.
- Isolation is also what gives accuracy: letting options attend to each other costs 5.2 and 2.9 points, mostly on the held-out JevBench (11.5 and 5.0); Prism-1 beats Set-LLM by 4.0 and 5.9.
- Cheapest read: 221 tokens vs 282 for SCQ on Banking20, with calibration on par (ECE 5.3% / 5.4% vs 4.9% / 5.4%).
- Comparison does not buy accuracy back: a gated cross-option channel changes accuracy by -0.2 points while breaking the axiom.

## Limitations admitted by the authors
- Needs fine-tuning: untrained it answers only 28.5% and 32.5% of validation questions; with an answer slot it is usable but below SCQ (69.9% / 63.3% vs 75.9% / 66.2%).
- Cannot handle decisions defined by the other options ("none of the above", "odd one out"), since comparison inside the model is forbidden by design.
- Protects the choice among options, not the state: text injected into the state reaches every option's score.
- Near-duplicates split probability: an added copy takes from every option in proportion rather than mainly from its twin, so the top probability drops; duplicates must be merged before the read.
- Weaker transfer: trails SCQ by 3.6 and 4.1 points on the held-out JevBench, plausibly because a read learned in fine-tuning transfers less than the instruction-tuned letter read.
- Narrow scope: at most 20 options, two 8-12B models, one to three seeds.

## What it leaves untried
- Applying the read to LLM-as-a-judge pairwise and listwise grading, where position bias is known; here response preference is only one benchmark domain.
- A state-side defence: injection immunity stops at the options, so end-to-end robustness is untested.
- Retrieval-scale option sets and larger models, where linear cost and the transfer gap could change the trade-off.
