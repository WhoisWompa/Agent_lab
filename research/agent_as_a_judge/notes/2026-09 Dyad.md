# Dyad: Extending Large Language Models with Native Typed Decision-Making

## One line
Adds a separate action encoder to a pretrained LLM so that, on a special token, the model scores a dynamically supplied list of typed actions directly (System 1) while still reasoning in text (System 2) in the same policy.

## Method
- **Problem.** LLM agents choose actions by generating action text token by token, so probabilities land on vocabulary tokens, not on the permissible actions. Dedicated System 1 models (Jev, Laya, SemIf, Simple Jev) score choices directly, but tie action scores to the evolving state or to fixed vocabulary tokens. Earlier native-action LLMs (ToolkenGPT, ExpA) need a fixed action set.
- **Idea: factorise the decision.** State: q_t = the LLM's hidden state at the decision position. Action: z_a = g(env description + action description), from a separate transformer plus a projector into the LLM's hidden size. When the LLM emits an interaction token, the policy is softmax(Z_t q_t) over the currently available actions; otherwise the ordinary LM head generates text. Assumed: the state needs no knowledge of the action list, and an action's meaning depends on the environment, not the moment.
- **Why it should work.** The split is an inductive bias toward reusable action representations, not one tangled state-action map. Action embeddings do not depend on history, so they are cached and reused; new actions are encoded once, and decision time costs only the LLM plus a dot product.
- **Training.** First the projector alone is aligned on synthetic action-selection examples (cross-entropy on the target action), so the two spaces start compatible. Then RL on task-outcome rewards (GRPO or GiGPO), treating tokens and typed actions alike as sampled decisions. It is trained either jointly (LLM plus encoder) or with the LLM frozen, training only the encoder as a plug-in module.

## Evaluated on
- Beats standard RL post-training in-domain in all 4 comparisons on Qwen3.5-9B: ALFWorld 90.90 vs 85.01 (GRPO), WebShop 83.65 vs 81.52 (GiGPO).
- Transfers to unseen environments: better than the matching RL baseline in 41 of 48 cross-environment comparisons (trained on DIVE or CodeGym, tested on ALFWorld, WebShop, tau2-bench, SWE), and better than the untrained model in 47 of 48.
- Frozen-LLM adaptation helps without touching LLM weights: Qwen3.5-4B ALFWorld 23.45 to 27.75, but joint training still reaches 31.52.
- Hurts general skills less: after ALFWorld/WebShop training, GRPO and GiGPO drop below the original model on every capability benchmark; Dyad beats them in all 24 pairs (9B HMMT 42.90 vs 35.13 GRPO, original 39.75).
- Competitive with Jev as a direct decision model: JevBench public subset 86.18% vs Jev 85.01%, hard tier 72.08 vs 70.88. Without reasoning, 83.52% at 0.31 s vs Jev's 0.67 s API latency.

## Limitations admitted by the authors
- The Jev latency comparison is not matched: Jev's 0.67 s comes from published API timings that include network overhead, so the speed claim is not a same-hardware result.
- The alignment test split is not an independent holdout: that pool was used in earlier model selection, so the authors call it a diagnostic.
- Overlap between the synthetic alignment actions and downstream benchmark actions was not checked, so some transfer may come from familiar actions.
- MCP-style descriptions beat natural language (+2.87 ALFWorld, +4.39 WebShop) but are far longer (265.57 vs 132.64 tokens on ALFWorld), so format is not separated from length and content.
- Retention is not full: at 4B several capability scores stay below the original model, and 9B HMMT stays below the original after WebShop training.

## What it leaves untried
- No test as a judge: the JevBench items include yes/no and ordinal ratings, but the paper does not check whether softmax(Z_t q_t) is calibrated, or whether scores hold when descriptions are reworded. Both matter before using it as an evaluator.
- The action encoder never sees the task context, by design. Actions whose meaning depends on the state (argument-heavy calls, SWE's single Bash tool) get no help from it. Dyad loses to the baseline on SWE in 3 of 12 cross-environment cells, and that is not analysed.
- No agentic head-to-head with Laya, SemIf or Simple Jev, so the gain from factorising, versus from having any decision head, is not isolated.
