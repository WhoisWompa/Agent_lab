# Jeva: System One Models from First Principles

## One line
A decision-native architecture for fast choose/yes-no/score judgments that encodes request and options separately, making decisions order-invariant, null-aware, scalable to thousands of options and cacheable across requests.

## Method
**Problem.** Current system-one models put the request and all candidates into one text and read the decision from answer-token logits. This lets candidate position affect the decision. It caps how many candidates there can be. Softmax over the candidates cannot tell "none fits" from "unsure which fits". And option text from a fixed registry or rubric is re-encoded on every request.

**Idea.** Keep the semantic encoding apart from the judgment that depends on the set:
- A shared backbone (Qwen3.5-4B) encodes the request into a state vector and each option on its own, without the question or the other options.
- One small decision block updates only the request state by attending over the fixed option memory. The attention sum is symmetric, so reordering options only reorders the sum: permutation-equivariant probabilities with no consistency loss (Proposition 3, exact arithmetic).
- **Set dependence is kept.** With independent scoring, a third option can never flip A vs B, because their log-odds ignore it. Proposition 1 builds one-block parameters where swapping the third option reverses A vs B, so reusable features do not force independent decisions.
- **Coverage is separate from competition.** A gate rho = sigmoid((max score - threshold)/temperature) gives the null probability, and p_i = rho * q_i. Options below the maximum leave rho unchanged (Proposition 2). A "None" slot in a flat softmax pays a forced log K penalty, so null gets rarer as options grow.
- **Caching.** Option vectors and per-layer key/value projections hold no request content, so they can be cached and assembled into new sets with identical outputs. Cost is linear in K.
- One readout serves Choice (argmax), Noul (probability of "true") and Score (expected rubric value).

## Evaluated on
- **No order sensitivity:** 0.00% flips on 600 Choice examples across orderings (mean TV 3.17e-8), vs 17.00% for Jev-1.13.0, 22.67% for InternDecision-4B and 26.17% for JevK5.
- **Null detection:** 98.66% AUROC on BANKING77 with K=16, vs 93.61% for KEV-BF16 and 79.44% for JevK5. At 5.02% FPR it catches 93.88% of answer-absent cases.
- **Accuracy:** best in 7 of 8 slices, above 90% on BANKING77 and MASSIVE. Mind2Web cross-task is 79.99% vs 66.26% for the next model. Typed Decisions is the exception: 78.30% vs InternDecision-4B's 78.70%.
- **Scale:** 78.40% aggregate accuracy on tool retrieval up to K=2,048, vs 64.00% for recursive JevK5. InternDecision supports only 65/84 requests even at K=32.
- **Reuse:** with full option reuse on new long-document sets, median latency falls from 2,102 ms to 75.1 ms (27.98x). No decision changes; the largest probability difference is 0.00736.

## Limitations admitted by the authors
- The symmetry and cache-equivalence proofs assume exact arithmetic. Floating-point and batching changes can move nearly tied scores, which is why cached outputs differ by up to 0.00736 in probability.
- When two options tie for the maximum, a first-index argmax can pick a different member after a permutation. Invariance holds only with identity-based tie-breaking.
- Proposition 1 shows a capability, not that training learns it. How often the trained model actually reverses preferences is never measured.
- Coverage does not depend on K, but the final joint argmax still does: under uniform competition, null wins only when logit(rho) < log K. So the null *decision* still shifts with set size.
- The cache must be cleared after any change to weights, tokenizer or templates, so reuse helps only with a frozen model.

## What it leaves untried
- The options are encoded without seeing the question. Judgments where an option's meaning depends on the request are left to a single small block. Whether that suffices for hard, request-specific rubrics, as agent evaluation needs, is untested.
- Score is tested only on Typed Decisions rubric examples (Score RMSE 0.3222, about level with InternDecision-4B's 0.3208). It is never tested as a judge of free-form or agent outputs against human preferences, although the paper names "evaluating responses against the same rubric" as a use case for caching.
