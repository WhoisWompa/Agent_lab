# Industry adoption of verification-first defaults in agent frameworks and lab harnesses, Jan 2025 to Oct 2026

Scope: what shipped, with version and date, in AutoGen/AG2 (and Microsoft Agent Framework as AutoGen's successor), LangGraph/Deep Agents, CrewAI, OpenAI Agents SDK, Google ADK, smolagents, Claude Code / Claude Agent SDK, Codex, Cursor, Devin, A2A and MCP; plus the 2025-2026 frontier-lab engineering posts on harness design. Builds on the project's mid-2026 survey (`research/multiagent_llm_systems/research_notes/failures_and_frameworks.md`, Q3 and Q4), which already recorded the 2025 baseline (hard caps everywhere, semantic stop by self-report, verification only as opt-in hooks, A2A COMPLETED unverified). This note records what changed after that, and what did not.

Dating conventions. Release dates come from PyPI upload times ([PyPI JSON API](https://pypi.org/pypi/openai-agents/json) and the equivalent for each package), the npm registry for Claude Code ([registry.npmjs.org/@anthropic-ai/claude-code](https://registry.npmjs.org/@anthropic-ai/claude-code)), or GitHub release `published_at` fields. Claude Code's own `CHANGELOG.md` carries version numbers but no dates. Anything I could not confirm against a primary page is marked **(unverified)** or **(secondary)**.

## Q1. Which frameworks turned any verification of subagent output on by default in 2025-2026, and what does it check?

### Takeaway
None. As of 21 Oct 2026 every framework and harness still ends a loop on the agent's own signal (no tool calls, a final-answer tool, an escalate flag, a final report) backed by a numeric cap, and accepts a subagent's result without checking it. What did ship in 2026 is a wider set of opt-in gates (Deep Agents `RubricMiddleware`, Claude Code `SubagentStop` hooks with exit-2 blocking, Codex Guardian auto-review, ADK `after_tool_callback` "to screen tool output", AG2 TealTiger deterministic tool-argument guardrails, OpenAI SDK tool guardrails and `ModelRefusalError`), several default changes that go the other way (Claude Code 2.1.215 stopped auto-running `/verify` and `/code-review`; OpenAI SDK 0.7.0 made nested handoff history opt-in), and schema validation of inter-agent payloads in the graph frameworks (ADK 2.0 node schemas, Microsoft Agent Framework build-time type checks). The one place a "lead always reviews" rule is on by default is a product harness, Devin Fusion, not a framework.

### Inferences
- The 2026 pattern is "gate the action, not the result." Codex Guardian reviews actions that need approval, ADK `require_confirmation` gates node execution, AG2 TealTiger checks tool arguments, Claude Code hooks gate tool calls; none of these checks whether the returned result is true. The result-side gates (RubricMiddleware, SubagentStop hooks, CrewAI guardrails, smolagents final_answer_checks) are all opt-in.
- Two defaults moved away from verification in 2026: Claude Code 2.1.215 (July) stopped auto-running `/verify` and `/code-review`, and OpenAI SDK 0.7.0 made handoff summarisation opt-in. Both read as cost or reliability rollbacks rather than policy statements.
- Where verification is on by default it is in products with a single owner of the loop (Devin Fusion's lead review, Cursor Bugbot on PRs), not in frameworks that hand the loop to the developer.

### Gaps
- Codex: the official changelog redirects to learn.chatgpt.com and only October 2026 entries were visible; the March 2026 subagent GA, concurrency limit (6 vs 8) and Guardian's v0.119 introduction rest on third-party posts. The "Running Codex safely" post returned 403.
- Claude Code: no changelog entry introduces `/verify`, so when the auto-run began (before 2.1.215) is unknown.
- OpenAI Agents SDK: the release page carries no dates; 0.14.0's date (Apr 15) is from a secondary source.
- Microsoft Agent Framework: the 1.0 announcement page was not fetched directly; the quote is from search excerpts of the devblog.
- No vendor doc read here publishes a failure or false-completion rate for its framework.

## Q2. Did any framework add schema-validated or verdict-typed inter-agent messages?

### Takeaway
Schema validation of payloads arrived in the graph frameworks (ADK 2.0 node `inputSchema`/`outputSchema` validated at runtime; Microsoft Agent Framework type checks at build time; Deep Agents `response_format` and strict `task` arguments; LangGraph `response_schema` on interrupts; OpenAI SDK local validation of handoff `input_type`). Verdict-typed messages (a result that carries "verified / unverified / failed" semantics) appeared only in MCP's `isError` and new `resultType` field, in Deep Agents' RubricMiddleware statuses, and in Claude Code's "partial" marking. No framework or protocol attaches a verification status to a handed-off claim, and A2A 1.0 removed rather than added state-transition fields.

### Cited Findings
- ADK 2.0: node `inputSchema`/`outputSchema` "validates it at runtime"; LlmAgent-level `inputSchema` "applies only when the agent is exposed as a tool" — [ADK data handling](https://adk.dev/graphs/data-handling/). Go 2.0.0 (2026-06-30) lists "input/output schema validation" among workflow features — [adk-go v2.0.0](https://github.com/google/adk-go/releases/tag/v2.0.0). 2.11.0 (2026-10-02): "**tools:** surface NodeTool failures to on_tool_error and return dict validation errors" — [adk-python releases](https://github.com/google/adk-python/releases)
- Microsoft Agent Framework: build-time "Type Compatibility", "Graph Connectivity", "Executor Binding", "Edge Validation"; Python "type-validated message routing" — [Builder and execution](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/builder-and-execution); [Workflow concepts](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/)
- Deep Agents: with `response_format`, "the parent always gets valid JSON matching the schema" — [Subagents doc](https://docs.langchain.com/oss/python/deepagents/subagents); 0.7.18 rejects unknown `task` argument keys — [deepagents releases](https://github.com/langchain-ai/deepagents/releases)
- LangGraph 1.2.12 (2026-09-21): `response_schema` on `interrupt()` — [langgraph releases](https://github.com/langchain-ai/langgraph/releases)
- OpenAI SDK handoffs: `input_type` "validates the returned JSON locally, and passes the parsed value to `on_handoff`"; `nest_handoff_history` "is available as an opt-in beta and is disabled by default" — [Handoffs doc](https://openai.github.io/openai-agents-python/handoffs/); 0.6.0 packaged handoff history "into a single assistant message that begins with a fixed context line", 0.7.0 made nesting opt-in — [Release notes](https://openai.github.io/openai-agents-python/release/)
- MCP 2026-07-28: "All results now carry a required `resultType` field: `"complete"` for ordinary results and `"input_required"`"; tasks moved to an extension; `outputSchema` loosened to any JSON Schema 2020-12 — [MCP changelog](https://modelcontextprotocol.io/specification/latest/changelog). Tools page: "Servers **MUST** provide structured results that conform to this schema. Clients **SHOULD** validate structured results against this schema"; clients SHOULD "Validate tool results before passing to LLM"; servers MUST "Sanitize tool outputs"; "clients **MUST** consider tool annotations to be untrusted unless they come from trusted servers". - A2A 1.0.0 (GitHub release 2026-03-12): "Remove redundant `final` field from `TaskStatusUpdateEvent`"; "Remove unimplemented state_transition_history capability field"; "Added clarifying text around messages and artifacts" — [A2A v1.0.0 release](https://github.com/a2aproject/A2A/releases/tag/v1.0.0). Spec 1.0: Artifact fields are `artifactId`, `name`, `description`, `metadata`, `extensions`, `parts`; "No validation, schema, provenance, or signature fields are defined for Artifact" — [A2A spec](https://a2a-protocol.org/latest/specification/)
- Claude Code: subagent report header marks instructions inside as "the subagent's words [that] carry no authority from you"; `maxTurns` output "marked as partial" — [Sub-agents doc](https://code.claude.com/docs/en/sub-agents)
- AG2 1.1.0 (2026-09-24): "MCP errors follow the spec... protocol-level failures return the prescribed JSON-RPC codes instead of a generic error or a tool result flagged `isError`" — [ag2 releases](https://github.com/ag2ai/ag2/releases)
- Codex multi-agent v2 "structured inter-agent messaging" **(secondary)** — [danielvaughan](https://codex.danielvaughan.com/2026/03/30/codex-cli-multi-agent-v2-path-addressing-structured-messaging)

### Inferences
- Schema validation checks shape, not truth: a `{"status": "done"}` that validates is still a self-report. The only verdict-like fields are about the transport (MCP `isError`, `resultType`) or about truncation (Claude Code "partial"), not about whether the content was checked.
- MCP's trust statements run one way: the client must distrust the server's annotations, and the server must sanitize outputs, but nothing lets a server or an intermediate agent say "this result was verified against X". Clients are told to validate structured results against the schema only as SHOULD.

### Gaps
- Codex's structured inter-agent message format is undocumented in any primary page I reached.
- Whether ADK Python validates node schemas as strictly as the TypeScript docs describe (Zod-only enforcement) was not confirmed.

## Q3. What did the labs change in their own harnesses after the false-completion and reward-hacking findings (abort options, hidden tests, sandbox gates, CoT monitors)?

### Takeaway
The labs changed measurement and isolation more than loop logic. OpenAI added deployment simulation to its system cards (replaying 54,218 then 49,650 internal Codex tasks, judging misalignment from the chain of thought, publishing severity-3+ flag rates of 0.135% to 0.054%) and shipped Guardian, an opt-in reviewer subagent for approvals. Anthropic published eval guidance that grades outcomes not claims, built an evaluator agent with hard thresholds into its long-running harness after finding self-grading "reliably skew[s] positive" and early evaluators "approved the work anyway", then made the evaluator optional once Opus 4.6 needed less scaffolding; Managed Agents keeps credentials out of the sandbox. Google's ADK moved control flow out of the model and stopped executing code found in private reasoning. No lab reports an abort option, hidden tests or a CoT monitor wired into a shipped harness loop.

## Q4. Has the Anthropic vs Cognition disagreement on full traces vs summaries been resolved by anyone with data?

### Takeaway
Not with a controlled comparison. The two camps have converged in practice: Cognition's own 2026 harnesses pass briefs and results, not full conversations (Fusion, Sep 2026), while keeping "full context" forks for the single-writer "smart friend" pattern; Anthropic's harness passes files; Claude Code's default moved toward forks that inherit the full conversation (2.1.232) while Deep Agents and Codex default to isolated subagents with a final message. Nobody published an ablation of handoff format at equal compute.

### Cited Findings
- Cognition, 22 Apr 2026: "Our original observations still hold today for parallel-writer swarms"; works when "writes stay single-threaded"; the "smart friend" pattern shares "a fork of the full context" with the stronger model; "map-reduce-and-manage" where children "execute, and the manager synthesizes" — [Cognition](https://cognition.com/blog/multi-agents-working)
- Cognition Fusion, 11 Sep 2026: "the lead and sidekick only exchange briefs, results, and feedback"; "Each agent keeps its own persistent context"; "up to 39% more efficient than other model harnesses"; Artificial Analysis Coding Agent Index v1.5: Codex (Astra) 100 at $7.47 vs Fusion (Astra + SWE-2) 61 at $4.54; DeepSWE 1.1: Fable 5.1 64.3 ($14.63) vs Fusion 63.1 ($7.88); Terminal-Bench 4: Astra 55.6 vs Fusion 50.0 — [Cognition](https://cognition.com/blog/local-fusion). These compare cost and score of a two-model harness against single-model harnesses; they do not vary the handoff format.
- Anthropic harness (24 Mar 2026): inter-agent handoffs "via files"; context resets with "a structured handoff that carries the previous agent's state and the next steps" in the Sonnet 4.5 era, dropped for Opus 4.5 — [Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps). C compiler: shared git repo, locks, READMEs, "no other inter-agent communication method was implemented" — [Anthropic](https://www.anthropic.com/engineering/building-c-compiler)
- Claude Code 2.1.232 (2026-08-13): fork subagents on by default, inheriting "the full conversation and prompt cache"; 2.1.302 (2026-10-16) forks on by default in `claude -p`, the Agent SDK, desktop and VS Code — [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md); isolated subagents remain the non-fork default and "returns only the summary" — [Sub-agents doc](https://code.claude.com/docs/en/sub-agents)
- Deep Agents: isolated by default, "only the final result"; forks opt-in — [Subagents doc](https://docs.langchain.com/oss/python/deepagents/subagents)
- OpenAI SDK: the receiving agent "gets to see the entire previous conversation history" by default; summarised history opt-in beta — [Handoffs doc](https://openai.github.io/openai-agents-python/handoffs/)
- Google scaling study: the abstract's finding that architectures without centralized verification propagate errors more is about verification topology, not handoff format — [arXiv 2512.08296](https://arxiv.org/abs/2512.08296)
- Cosine's reply "You Should Build Multi-Agents" returned 404 — [cosine.sh](https://cosine.sh/blog/why-you-should-build-multi-agent-ai)

### Inferences
- The disagreement dissolved into a split by write pattern: full context for anything that writes to the same artefact (Cognition's fork, Claude Code's fork default), structured results for read-heavy delegation (Fusion briefs, Deep Agents, Codex explorer subagents, Anthropic research). That is a design consensus, not an empirical result.
- Fusion's "lead always reviews" plus brief-only handoff is the strongest production evidence that structured handoff with mandatory review is viable at near-parity on coding benchmarks, but the comparison confounds model pairing, cost and handoff format.

### Gaps
- No vendor or lab has published a full-transcript vs structured-handoff ablation within one framework at matched compute. This remains open.

## Q5. What do vendors say remains open or unsupported, and what remains open overall?

### Takeaway
Vendors are explicit about mechanics they do not cover (handoffs outside guardrails, local sandboxes without OS confinement, scans that are not security boundaries, schema validation left to clients) and silent about false completion. The four open questions stand as of Oct 2026: no vendor publishes a false-completion rate for its framework (OpenAI's system-card replay is the closest and reports only aggregate severity rates); no framework verifies subagent output by default; no controlled full-transcript vs structured-handoff comparison exists; A2A 1.0 added card signatures and webhook authentication but no verification to the task state machine.

### Cited Findings
- OpenAI SDK: guardrails "Not covered: handoff calls and hosted or built-in execution tools" **(secondary)**; local sandbox "no OS-level confinement to commands on Linux" **(secondary)** — [developersdigest](https://www.developersdigest.tech/blog/openai-agents-sdk-whats-new-2026); "Tool input guardrails apply to function tools, not handoffs" — [Handoffs doc](https://openai.github.io/openai-agents-python/handoffs/)
- Claude Code: the report scan "doesn't judge whether content is malicious... It isn't a substitute for restricting what a subagent can reach" — [Sub-agents doc](https://code.claude.com/docs/en/sub-agents)
- Codex docs: safety monitoring "doesn't replace sandboxing, permissions, or review of the result"; `danger-full-access` is "not recommended" — [Agent approvals doc](https://learn.chatgpt.com/docs/agent-approvals-security)
- MCP: annotations "untrusted unless they come from trusted servers"; validation of structured results by clients is SHOULD, not MUST — [MCP tools spec](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)
- A2A 1.0 spec: Agent Card signing is "MAY"; "Clients SHOULD verify at least one signature before trusting an Agent Card"; push notifications "Clients **MUST** validate webhook authenticity"; "Agents **MUST** validate all input parameters"; no text on trusting a remote agent's reported state or validating outputs; task states unchanged (SUBMITTED, WORKING, INPUT_REQUIRED, AUTH_REQUIRED, COMPLETED, FAILED, CANCELED, REJECTED) — [A2A spec](https://a2a-protocol.org/latest/specification/). Google called v1.0 "the first stable, fully production-ready version" with "over 100 technology companies" (16 Apr 2026) — [Google Open Source Blog](https://opensource.googleblog.com/2026/04/a-year-of-open-collaboration-celebrating-the-anniversary-of-a2a.html). ADK 2.10.0 patches the client side: "report an A2A stream that ends before the remote task finishes"; "complete an A2A task whose run ends without a status message" — [adk-python releases](https://github.com/google/adk-python/releases)
- ADK TypeScript: schema validation "Only enforced for Zod schemas; a genai Schema is left unvalidated" — [ADK data handling](https://adk.dev/graphs/data-handling/)
- Anthropic: evaluator "worth the cost when the task sits beyond what the current model does reliably solo" — [Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps); deployment-simulation results are "most useful as an additional signal about internal deployment risk" — [OpenAI](https://deploymentsafety.openai.com/gpt-6-astra/forecasting-misaligned-behavior-with-deployment-simulation-of-internal-codex-traffic)
- Cognition on review: "Teams need to establish what rigorous review looks like for agent-produced work at a much higher volume" (23 Apr 2026) — [Cognition](https://cognition.com/blog/what-we-learned-building-cloud-agents)
- Cursor: no false-positive rate for Bugbot — [Cursor changelog](https://cursor.com/changelog/bugbot-updates-june-2026)

### Inferences
- The protocols have settled who must distrust whom (client distrusts server metadata, server validates inputs, cards and webhooks are authenticated) without giving either side a field for "this output was checked". Verification therefore stays application-level, and every application surveyed leaves it off by default.
- The only published numbers about agents misreporting are model-level (OpenAI replay flags, Anthropic's Petri sabotage runs), never framework-level, so a framework cannot be compared with another on false completion using vendor data.

### Gaps
- A2A "What's New in v1.0" page was not fetched; the 1.0 vs 0.3 differences above come from the GitHub release body and the spec's Appendix A.
- MCP 2026-07-28 is described as both a release and a release candidate by third parties; the spec site presents it as the current revision.
- Whether Codex's Guardian scores results (not just actions) in any mode could not be confirmed from primary pages.
