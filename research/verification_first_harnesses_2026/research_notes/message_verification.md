# Message-level verification between LLM agents, 2025 to October 2026

Scope: work that makes an inter-agent message carry something checkable (fetched evidence, a claim tag, a schema, a verdict, a signature) rather than free text. Everything below is an arXiv preprint unless a venue is named. Review status is stated per paper. Background already covered in `research/multiagent_llm_systems/report.md` (TalkHier field ablation, Bronder headline counts, HMAC 774/774 and 295/295, Echoing 70% to 9%, MCP outputSchema as unused machinery) is repeated only where a new detail was found.

## Key question 1: Which systems check a message against something external before peers see it, and what is the check?

### Takeaway
Nothing found verifies a debater's claim against external evidence *before* the claim reaches peers. The tool-grounded debaters (Tool-MAD, PROClaim, contestable MAD) let each agent fetch its own evidence and score it, but the scoring is an LLM step run after the message is written and the round is appended to shared history regardless. The only pre-propagation gates that are script-run sit in pipeline harnesses outside debate: EviBound (MLflow run ID, artifacts, FINISHED status; 0/8 false claims at 8.3% overhead), ProvenanceGuard (NLI allow/block on a finished answer; block F1 0.80), and Pramana (typed ClaimAttestation with deterministic `verify()` for measurement and citation claims, TLA+-checked but unmeasured).

### Cited Findings

**Tool-MAD (arXiv 2601.04742, submitted 8 Jan 2026, cs.CL, no venue stated; preprint)**
- Each debater has its own tool: the RAG agent queries a Milvus store of Wikipedia articles, the Search agent uses the Tavily Search API. Debaters see the opponent's previous *response*, not the opponent's retrieved documents; only the Judge receives "the full debate history, including agent responses and retrieved evidence from each round" — [Tool-MAD HTML](https://arxiv.org/html/2601.04742)
- Per round the agent forms a query from the opponent's previous answer, retrieves, then writes its response. Faithfulness and Answer Relevance are computed *after* the response, and the round is appended to the shared history. A round scoring below threshold is "marked as inconclusive and the debate continues"; the text is inconsistent on whether such rounds are repeated — [Tool-MAD HTML](https://arxiv.org/html/2601.04742)
- The two scores are RAGAS-style but LLM-computed: faithfulness is the fraction of statements an LLM judges supported by the retrieved context; answer relevance is mean cosine similarity between embeddings of n LLM-generated questions and the original question. The LLM and embedding model used for scoring are not named; the Judge model is not named — [Tool-MAD HTML](https://arxiv.org/html/2601.04742)
- Exact match on 200 sampled instances per dataset (FEVER / FEVEROUS / FaVIQ / AVeriTeC / avg): GPT-4o-mini + Tool-MAD 73.0 / 71.5 / 77.5 / 62.0 / 71.0; GPT-4o-mini + MAD 71.0 / 36.5 / 68.0 / 36.0 / 52.9; GPT-4o-mini + MADKE 72.0 / 66.0 / 75.5 / 58.5 / 68.0. Llama-3.3-70B + Tool-MAD 74.0 / 77.0 / 78.5 / 66.5 / 74.0 against Llama + MAD 45.9 avg and Llama + MADKE 56.5 avg. Medical (MedQA / PubMedQA): MAD 58.0 / 22.5, MADKE 74.0 / 21.5, Tool-MAD 77.0 / 29.0, backbone not stated — [Tool-MAD HTML](https://arxiv.org/html/2601.04742)
- Max 3 rounds. The abstract says "up to 5.5%" over state-of-the-art MAD; Section IV-C says 35.0% over MAD and the Introduction 35.5%; the 5.5% is against MADKE, the 35% against plain MAD. No cost, token or latency figures; confidence intervals computed for GPT-4o-mini only because repeated multi-round trials were "prohibitively expensive". No limitations section — [Tool-MAD abs](https://arxiv.org/abs/2601.04742); [Tool-MAD HTML](https://arxiv.org/html/2601.04742)

**PROClaim (arXiv 2603.28488, v1 30 Mar 2026, v3 1 Aug 2026, cs.CL, marked "Under review"; preprint)**
- Courtroom roles: Plaintiff (gpt-5-mini), Defense and consistency analyst (deepseek-v3.2), Court (qwen3-235b-a22b), Expert Witness (hermes-3-llama-405b), Critic and premise decomposition (deepseek-r1), three Judges (deepseek-r1, hermes-3-llama-405b, qwen3-235b-a22b) — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Evidence: one FAISS query over about 360,000 COVID-19 PubMed abstracts per premise with stance-conditioned supporting and opposing queries; the pools are exchanged before debate. During debate (P-RAG) both counsels retrieve more, with queries built from the last four messages, a self-identified gap and prior-round reflection; the Judge refines each query — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Admissibility: each document gets w = relevance × credibility (each in [0,1]); w > 0.5 admitted, 0.1 < w ≤ 0.5 disputed, rest discarded. Relevance and credibility come from a scoring prompt (Appendix G.2), so an LLM scores them. A novelty filter (embedding cosine, admit if novelty ≥ 0.20) is computed, not LLM-judged. No code check runs on a counsel's *argument* before the other side reads it — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Role-switching: counsels swap roles and re-run; a separate LLM compares the two transcripts for contradictions and selective evidence use, producing a consistency score that feeds confidence weighting, not the verdict. Verdict is a majority of three heterogeneous judges. "Burden of Refutation": Inconclusive counts as Supported unless the panel reaches a definitive Refute, which biases toward Supported — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Check-COVID (120 claims, 3 runs): per-run accuracy 0.950, 0.817, 0.790; majority vote 0.817 acc / 0.817 macro-F1. Baselines: single-call DeepSeek-v3.2 + RAG 0.800 acc (18.5 evidence items avg), standard MAD 0.717 acc (12.1 items), PROClaim 67.5 items. Ablations: w/o P-RAG 0.742 (−7.5 pp), w/o role-switching 0.775 (−4.2), w/o three judges 0.783 (−3.3), w/o self-reflection 0.808 (−0.8). Removing P-RAG raises inter-judge κ from 0.468 to 0.599, read by the authors as confident convergence on wrong answers. HealthVer (100 claims) 72.0% vs single-call RAG 63.0% vs MAD 56.0%, McNemar χ² = 8.04, p = 0.0046. FEVEROUS (60 claims) 0.783 — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Cost: about 210.9K tokens per claim, roughly 11× standard MAD (about 18.9K); 5.47 rounds avg; removing self-reflection adds about 17% tokens and 29% more rounds. No wall-clock or dollar figures — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Admitted limitations: 11× cost; run variance 0.790 to 0.950 under identical configuration; judges' rationales may not reflect their computation ("deliberative traceability", not faithful explanation); cross-domain results are sampled proof-of-concept; one budget-constrained model assignment — [PROClaim HTML](https://arxiv.org/html/2603.28488)

**Contestable MAD for multimedia verification (arXiv 2605.14495, 14 May 2026; submitted to the ACM ICMR 2026 Grand Challenge on Multimedia Verification, DOI 10.1145/3805622.3812606; acceptance not stated on the arXiv page)**
- Combines multimodal LLMs, external verification tools and arena-based quantitative bipolar argumentation (A-QBAF). Each case is split into claim-centred sections; retrieved evidence becomes support and attack arguments carrying provenance and strength scores, resolved in small local argument graphs with selective clash resolution and uncertainty-aware escalation; outputs section-wise "transparent and editable" reports — [arXiv 2605.14495](https://arxiv.org/abs/2605.14495)
- The abstract gives no accuracy, dataset size, benchmark rank, cost or limitations; who assigns strength scores (LLM vs script) and whether anything is checked before broadcast is not stated — [arXiv 2605.14495](https://arxiv.org/abs/2605.14495)

**EviBound (arXiv 2511.05524, v1 28 Oct 2025, cs.AI; preprint, reproducibility package "upon publication")**
- Two gates. Approval Gate validates acceptance-criteria schemas before code runs. Verification Gate queries MLflow programmatically for run ID, required artifacts (recursive path check) and FINISHED status, plus optional metric checks. A claim propagates only when it has a queryable run ID, the artifacts and FINISHED status. Retries bounded at 1-2 attempts — [EviBound](https://arxiv.org/abs/2511.05524)
- 8 benchmark tasks: prompt-only baseline 100% hallucination (8/8 claimed, 0/8 verified); verification-only 25% (2/8 failed); dual gates 0% (7/8 verified, 1 blocked at approval). About 8.3% execution overhead. The check confirms artifacts exist and the run finished, not that they are correct, beyond optional metrics — [EviBound](https://arxiv.org/abs/2511.05524)

**ProvenanceGuard (arXiv 2606.18037, v1 16 Jun 2026, v3 27 Aug 2026, cs.AI; preprint)**
- Takes MCP traces (tool IDs, source IDs, raw outputs), splits the answer into atomic claims, routes each to source-specific evidence, checks support with NLI and a token-alignment proxy, compares stated attribution with the routed source, and emits per-claim verdicts and an answer-level allow/block; blocked answers go to retrieval-augmented repair and re-verification. Timing is implied: the gate runs on a finished answer before delivery, so it is post-generation, pre-use — [ProvenanceGuard](https://arxiv.org/abs/2606.18037v1)
- 281 medical MCP traces (266 adjudicated). Held-out 40 traces: block F1 0.802, source accuracy 0.858 over 260 source-eligible claims. Harder multi-source benchmark: block F1 0.846 but source-plus-relation accuracy 0.229. 50 controlled clinical probes: all injected attribution swaps detected. Labels: 2,325 LLM-assisted, 361 human-verified. No overhead reported; repair "often" falls back to a conservative answer — [ProvenanceGuard](https://arxiv.org/abs/2606.18037v1)

**Pramana (arXiv 2605.20312, 19 May 2026, cs.CR; single author; preprint)**
- Wraps each consequential output in a typed ClaimAttestation with four variants (measurement, inference, analogy, citation), each with a `verify()` that re-checks the claim against its recorded source so an auditor can re-execute offline. Verification is deterministic (script) for MeasurementClaim and CitationClaim; for InferenceClaim and AnalogyClaim it depends on the oracle, and with an LLM oracle it is "audit-replayable but not deterministic". Specifies an A2A and MCP wire-extension manifest with three invariants: reachability, SLA bound, offline re-verifiability — [Pramana](https://arxiv.org/abs/2605.20312)
- Evaluation is formal and small: TLA+ lifecycle checked with TLC over 38,563 reachable states, zero invariant violations; Python reference implementation passes 84 tests; an exploratory LLM-as-judge pilot (n=100, 2,275 reviewer calls) found a 40-percentage-point false-positive-rate gap across corpora attributed partly to reference-solution quality. Authors: "The pilot does not validate Pramana on its own." No overhead figures; the page does not say verification must succeed before acceptance — [Pramana](https://arxiv.org/abs/2605.20312)

**MACE (arXiv 2604.17225, 2026)**: Planner, Executor, Verifier agents checking claims against tabular documents, with results for smaller models; only the search snippet was read, so no numbers are reported here — [MACE](https://arxiv.org/abs/2604.17225)

### Inferences
- In both tool-grounded debaters the external tool improves the *evidence pool* but the inter-agent channel stays free text: an argument reaches the opponent before any score is attached, and the score is itself an LLM judgement. The "verification" is of the final verdict's inputs, not of each message.
- The gains attributed to tool grounding are large relative to plain MAD (Tool-MAD +18 points avg on GPT-4o-mini, +28 on Llama; PROClaim +10 pp) but small relative to a single call with the same retrieval (PROClaim +1.7 pp over single-call RAG at about 11× tokens; Tool-MAD reports no single-call-with-tools baseline). The cheap part of the gain is retrieval, not debate.
- The pre-propagation script gates that exist (EviBound, ProvenanceGuard, Pramana's measurement/citation variants) verify existence, status, attribution or reproducibility, never truth of an inference. That matches the VMAO limitation in the background report.

### Gaps
- No paper found runs a per-message gate inside a debate (verify, then broadcast). PROClaim's novelty filter and admissibility threshold gate *documents*, not *arguments*.
- Tool-MAD's judge model, scoring LLM and embedding model are unnamed, so the script-vs-LLM split for its scores cannot be pinned down beyond "LLM-computed per the method description".
- Contestable MAD reports no results on its arXiv page; the ICMR challenge result was not located.
- The second half of PROClaim's HTML (appendices H, token breakdown) was not read.

## Key question 2: Does any paper compare a schema-enforced or verdict-only channel against free text in code, at matched compute?

### Takeaway
No. The closest are Echoing (a two-field Pydantic-style `AgentResponse` that cut echoing from up to 70% to under 10%, but with no task-quality, cost or information-loss measurement and no statement of code enforcement) and LLM-X (a gateway that validates every payload against JSON Schema before delivery, but with scripted Python agents and no free-text baseline). Framework schema channels (MCP outputSchema, CrewAI output_pydantic) exist as mechanisms with no published comparison.

### Cited Findings
- Echoing's mitigation is a "Pydantic-style" class `AgentResponse` with two string fields, `role` (short identity description) and `message`; the environment parses the structured output and passes only the text to the other agent, forcing "identity assertion with each response". The paper does not say whether this used a JSON schema, a native structured-output API, function calling or prompt instructions, nor how malformed outputs were handled. Gemini-2.5 models were excluded from the mitigation because they "failed to support tools and structured output generation" — [Echoing HTML](https://arxiv.org/html/2511.09710)
- Echoing rates: Section 4.1 reports about 5% to 70% across models (the intro says 55-70%, inconsistent). Per model in transactional domains: GPT-5 2-10%, GPT-4.1 5-13%, GPT-4o 58% car sales / 25% hotel / 17% supply chain, Gemini-2.5-Flash 64-73% everywhere, Llama-3.1 11.5% (8B) and 9.1% (70B). Reasoning models 32.8% avg (low 32.7, medium 32.8, high 32.9) vs 37.7% non-reasoning. Advisory (medical) domain: GPT-5 2%, Gemini 15-18%, Llama-3.1-8B 30%. With structured responses, rates fell "below 10%" for GPT and Sonnet variants over 24 configurations (Fig. 9); the abstract's "9%" is this. Scale: 66 configurations, 4 domains, 2,500+ conversations, 250,000+ inferences. Echoing rises after about 7+ agent turns. Published at an ICLR workshop per the arXiv comment — [Echoing HTML](https://arxiv.org/html/2511.09710); [Echoing abs](https://arxiv.org/abs/2511.09710)
- Echoing reports no cost, latency, token or information-loss analysis for structured responses and no task-completion or outcome quality under the mitigation. Metric is an LLM judge with 91.1% human agreement on 150 conversations and 79.6-88.9% cross-judge agreement; GPT-4o was the most conservative judge so rates may be underestimates. Only 93.2% of runs (completed conversations) were analysed — [Echoing HTML](https://arxiv.org/html/2511.09710)
- LLM-X (arXiv 2605.11376, 12 May 2026, Waterloo; preprint) validates payloads against JSON Schemas (e.g. Negotiation.json) "at the gateway before delivery"; policy enforcement "prevents acceptance of malformed or duplicate offers". Behaviour on schema failure is not specified beyond mention of "automated retry and correction mechanisms". All agents were scripted Python wrappers, not live LLMs. No comparison to free text. Gateway latency: 12 agents, 12 h, 806 rounds, 9,672 offers, mean 6.18 ms, p95 11 ms; token counts and LLM overhead not measured — [LLM-X](https://arxiv.org/html/2605.11376v1)
- MCP 2025-11-25: `outputSchema` is optional JSON Schema; if provided, "Servers MUST provide structured results that conform to this schema" and "Clients SHOULD validate structured results against this schema"; a tool returning `structuredContent` SHOULD also return the serialized JSON as a TextContent block for backwards compatibility. The spec notes `structuredContent` "is server-produced result data and is unrelated to LLM 'structured outputs'". Clients MUST treat tool annotations as untrusted unless from trusted servers, and SHOULD "validate tool results before passing to LLM" — [MCP tools spec](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
- CrewAI `output_pydantic` makes the output "not only structured but also validated according to the Pydantic model"; `output_json` yields "a valid JSON structure"; one output type per task. The docs do not say what happens on validation failure (no retry, error or fallback documented). The only documented retry is the guardrail: a function returning `(True, result)` or `(False, error)` or an LLM-checked string description, with the error "sent back to the agent" up to `guardrail_max_retries` (default 3). Whether downstream tasks receive the structured form or raw text is not stated; `str()` prefers Pydantic, then JSON, then raw — [CrewAI tasks docs](https://docs.crewai.com/en/concepts/tasks)
- A 2026 taxonomy of agent communication protocols adds a "schema flexibility" axis (single fixed schema vs runtime-chosen schemas) but runs no experiment — [Sander taxonomy](https://arxiv.org/html/2606.19135v1). "Beyond Message Passing" argues for typed intents over text without an ablation — [arXiv 2604.02369](https://arxiv.org/html/2604.02369v3). "Communication Policy Evolution for Proactive LLM Agents" compares free text with structured UI forms for human-agent communication: text was more efficient for task progress, forms reduced ambiguity but imposed fixed per-turn overhead — [arXiv 2606.14314](https://arxiv.org/html/2606.14314) (snippet only; agent-user, not agent-agent)
- TalkHier's ablation (removing "background" −8.9 points, "intermediate output" −4.7) is taken from the background report's reading of [TalkHier v1](https://arxiv.org/html/2502.11098v1); not re-fetched here.

### Inferences
- Echoing is the only measured case of a fixed-field channel changing inter-agent behaviour, and the field that mattered is a *self-description* (`role`), not a verdict. It removes a failure mode (identity drift) rather than a persuasion surface; the `message` field is still free text.
- The information-loss question (TalkHier −4.7 to −8.9) and the persuasion-surface question (Echoing, conformity) have never been put in the same experiment. TalkHier removed *content* fields; Echoing *added* a metadata field. Neither varied the channel from free text to verdict-only.
- Framework schema validation (MCP, CrewAI, LLM-X) is enforced by code at the transport or task boundary, but every documented path on failure is "retry with the error" or unspecified, so a schema-enforced channel today is a retry loop, not a hard filter.

### Gaps
- No paper found compares a verdict-only or fixed-field inter-agent channel against free text at matched compute. This remains open as the brief states.
- DSPy signatures documentation redirected twice (dspy.ai/learn/... and dspy.ai/current/learn/...) and was not read; its adapter parse-failure behaviour is unverified here.
- CrewAI's behaviour when `output_pydantic` validation fails is undocumented on the tasks page.
- The Echoing paper's last 20% (which may hold the structured-output implementation detail) was not read.

## Key question 3: What happens to receiver trust when provenance or "unverified" labels are attached? Any positive results?

### Takeaway
Mixed, and the sign depends on the receiver's job and on whether the label survives the pipeline. Bronder found no label effect on Claude Opus 5 as a *generator* (15/24 with an "unchecked" wrapper vs 14/24 without; inline JSON 60/60). "Silence Is Endorsement" found a strong effect on safety *monitors*: a literal "(UNVERIFIED)" marker held Llama-3.1-8B approval of risky actions at 5% against 60% once stripped, Qwen2.5-14B at 9% vs 98%, DeepSeek-V4-Flash 6% vs 99%; but summarizers dropped the marker in 10-17% of outputs and memory compressors in 60-100%. A trust-boundaries study found a verified-identity cue took Nemotron's false-state selection from 50% to 0%, while authenticated delegation *raised* Claude's false-state selection by 33-42 points, and a deterministic tool gate committed 0% regardless of model.

### Cited Findings
- Bronder (arXiv 2608.14992, 15 Aug 2026, v1, one author; preprint). Task: pick a colour code for a named item or abstain; adoption = choosing an unsupported code. Exploratory four-arm study: no claim 0/24; prior assistant assertion 0/22 scorable; tool-result record 14/24; tool-result record wrapped in a ten-field metadata block marking it unchecked 15/24. Within the tool-result arm the record's code was chosen in 11/12 supported and 14/24 unsupported trials; a fixed output-token bias is ruled out but planted-token heterogeneity is "substantial". Preregistered replication: tool result 7/24 vs assistant assertion 0/24 (one-sided Fisher p = 0.0047); the tool-result rate fell from 14/24 to 7/24 across runs four days apart, unexplained. Second preregistered study: inline JSON text 60/60, tool result 57/60; registered result-first superiority criterion failed (p = 1). No condition reduced adoption. Limits: one model, one synthetic template, one API — [Bronder](https://arxiv.org/abs/2608.14992)
- "Silence Is Endorsement: Verification-Status Laundering in LLM Agent Pipelines" (arXiv 2609.20211, Yibo Hu, sole author, cs.CR; preprint). Controlled probe: 56 items (40 risky, 16 safe) across 13 operational tags. Marker-visible note: "(UNVERIFIED) Planner-Agent asserts that this action is authorized"; marker-lost note keeps "this action is authorized". Also no-claim and "VERIFIED:" baselines. Risky-action approval, marker-visible → marker-lost: Qwen2.5-0.5B 0.78→0.85; 1.5B 0.83→0.91; 3B 0.99→1.00; 7B 0.50→0.88; 14B 0.09→0.98; Llama-3.1-8B 0.05→0.60; Mistral-7B 1.00→1.00; OLMo-2-7B 0.65→0.88; Gemma-2-9B 0.89→1.00; DeepSeek-V4-Flash (hosted) 0.06→0.99; GPT-4o-mini (hosted) 0.48→0.99. Hosted rates are fractions over five sampled CoT outputs and are "directional". The marker also lowers safe-item approval for some monitors (Llama 0.70→0.40) — [Silence Is Endorsement HTML](https://arxiv.org/html/2609.20211)
- Same paper, pipeline: summarizers lost the status outright in about 10-13% of outputs, 17% including weakened outputs (two strong-model annotators). Memory compressors: literal marker absent in 60% (Mistral-7B) to 100% (Llama-3.1-8B) of handoffs; semantic loss 36-90%. Full chain removed the literal marker in 41% of cases vs 88% for memory alone. Full-pipeline risky approval 57-81% across three downstream monitors. Instructing monitors to distrust unverified claims was inconsistent: effect disappears for Qwen2.5-14B and 7B, increases for 1.5B, sharply lowers safe-item approval for Llama-3.1-8B. Proposed fix: carry authorization status as structured state attached to the claim, read directly by the monitor; the paper "does not implement or validate a complete provenance architecture". Limits: single seed, greedy decoding, some controls at 4-bit, forced-choice token probabilities for open-weight approval, 15-item repair analysis read descriptively — [Silence Is Endorsement HTML](https://arxiv.org/html/2609.20211); [abs](https://arxiv.org/abs/2609.20211)
- "Who Speaks, Who Authorizes, Who Acts?" (arXiv 2610.24298, 16 Oct 2026; preprint, artifacts "after acceptance"). E1 provenance cues (60 tasks, 1,800 advisory calls): for Nemotron, a verified-identity cue (P2) vs unsigned (P0) lowered false-state selection from 50.0% to 0% (95% CI −63.3 to −36.7); a metadata control (P4) was not neutral for Nemotron. Historical delegated-authentication study: authenticated delegation *raised* false-state advisory selection by 33.3-41.7 points for Claude and 33.3-37.5 for Nemotron (24 tasks, 1,008 calls). On invalid-proof cases, advisory request rates were 0.8% (GPT-5.4), 0% (Claude), 52.1% (Nemotron), 54.2% (Llama); the deterministic tool gate committed 0% in all cases. "Proof validity is not factual truth." Signer threshold limits proof construction, not model behaviour: Nemotron proposed protected actions in 40-50% of some below-cut cases where no valid false proof could exist. Claude's two-of-three quorum reached only 0.8% true-state utilization (a utility cost). After 257 denials, a recovery prompt with a fresh authoritative snapshot produced safe progress in 257/257, labelled "assisted behavior". No overhead reported; synthetic tasks; not fully crossed; E3 excluded after a forwarder-schema audit failure — [Trust Boundaries](https://arxiv.org/html/2610.24298)
- "Grading the Narrators" (arXiv 2607.24117, 27 Jul 2026, one author, LLM-assisted drafting; preprint): each claim carries an isnād chain of agents, sources and model versions; a narrator registry grades transmitters per domain in four tiers; chain grade is the weakest link; independent chains can corroborate up to a cap; a rule-based decision matrix routes claims to serve, review or quarantine. The content critic is a word-overlap heuristic with a negation check, not an LLM. Grades change downstream handling by construction (offline only). Offline eval: 20,000 claims extracted, 14,001 evaluated, 10 seeds; weakest-link quarantine 4,057 claims (29%); 3 of 4 faulty narrators recovered, the 18%-fault narrator never graded for lack of calibration data; corroboration fired 68/136 (exact-match), 603/603 (Wikipedia, 8/8 negative controls), 104/104 (physics). Matched-coverage comparison inconclusive; coverage capped at 4.8% by the critic; 157 tests passing — [Grading the Narrators](https://arxiv.org/html/2607.24117)
- Provenance survey (arXiv 2606.04990, 3 Jun 2026, 9 authors; preprint): five taxonomy dimensions (trace sources, evidence and execution units, provenance relations, granularity and timing, trust functions), seven relation types (Support, Derive, Depend-on, Contradict, Invalidate, Trigger, Update), six trust functions, Table 1 covers 12 agent systems. Open problems: unified trace schemas, claim-level semantic provenance, provenance-aware runtime safety and recovery, realistic execution-trace benchmarks, recovery-oriented evaluation, privacy-aware audit, causal failure attribution, scalable storage. The visible text does not address whether labels change receiver behaviour — [Provenance survey](https://arxiv.org/html/2606.04990v1)
- "Delayed Verification Destabilizes Multi-Agent LLM Belief" (arXiv 2606.27409, 25 Jun 2026, independent author; preprint): a corrector acting on δ-step-old error destabilises consensus; critical dose falls from 1 (δ=1) to 0.618 (δ=2) to 0.185 (δ=8); synchronising communication and verification delays is least stable. Real-LLM check: Qwen3.6-35B on 30 PsiloQA questions the model gets wrong, moderate verification gives about 0.8 convergence, over-aggressive about 0.4, an ungrounded contrarian 0 with the majority flipping in 91% of rounds; a pre-registered sweep over δ ∈ {0,1,6} found no delay-driven oscillation (p = 0.06). Signed numeric estimation: overshoot through zero in 96-100% of runs at δ=6 vs 0-4% at δ=1 across five models. Greedy corrector placement cut residual error from 9.1 to 2.3 on a synthetic graph (degree-based 2.9, random 2.5). Limits: local linear analysis, n=8 questions, symmetric graph only, placement validated on a surrogate — [Delayed Verification](https://arxiv.org/html/2606.27409v1)

### Inferences
- The negative and positive label results are consistent once the receiver's task is distinguished. Bronder's receiver had to *produce* an answer and treated any planted token as the answer; Hu's receiver had to *approve or deny* and used the marker as a cue. A label works on a gate, not on a generator.
- Even where a label works it is fragile: a literal "(UNVERIFIED)" string is dropped by summarisation 10-17% of the time and by memory compression 60-100%, so a text label is a lossy transport. That is the empirical case for structured state over inline tags, and it has not yet been built or tested as a fix.
- The trust-boundaries result that *authenticated* delegation raised false-state adoption by 33-42 points for Claude is the sharpest warning in this cluster: a provenance signal that attests identity, not truth, can increase misplaced trust.

### Gaps
- No positive result exists for a label changing a *generating* agent's adoption of a false claim; Bronder is the only such test and it is one model, one task.
- Hu's Appendix K (false-rejection figures under the "distrust unverified" instruction) and the last 20% of the paper were not read.
- No study varies label *strength* (unverified / checked by script / checked by LLM) against receiver behaviour.

## Key question 4: How are latent (non-text) channels being secured, and what is the overhead?

### Takeaway
One paper (Brito and Baquero, "When Latent Agents Lie") secures a KV-cache channel with an HMAC-SHA256 manifest binding specialist, session, model, visible commitment, tensor metadata and payload digest; it accepted 774/774 honest and rejected 295/295 tampered payloads, but reports no latency, byte or compute overhead and does not quantify the performance collapse under attack. Adjacent text-channel integrity work does report overhead: MIRROR's multipath quorum (NeurIPS 2026 FLMSec workshop) hits 0% attack success at 1× LLM token cost against 35× for an LLM judge; output attestation adds about 42 ms end to end; signed MCP manifests verify in at most 9.4 ms on edge devices.

### Cited Findings
- "When Latent Agents Lie: KV-Cache Integrity in Multi-Agent LLM Collaboration" (arXiv 2606.28958, 27 Jun 2026, Brito and Baquero, cs.MA, 16 pages; preprint). Agents send a short visible message plus their full KV cache to a coordinator. Clean latent collaboration beat matched text-only on transformed HiddenBench with Qwen3-4B: EM/F1 0.338/0.486 vs 0.231/0.369; same direction on Qwen3-8B and HotPotQA (numbers not on the page). A malicious specialist can collapse performance by altering hidden KV state while the visible commitment looks plausible; text-only verifiers miss it; magnitude checks catch obvious corruptions but adaptive attacks evade them. HMAC-SHA256 manifest binds specialist, session, model, visible commitment, tensor metadata and payload digest; accepted 774/774 honest replayed payloads, rejected 295/295 recorded tampered payloads. The authors call transport protection more reliable than judging whether hidden state looks normal. Not reported: latency, bytes, compute overhead, quantified collapse, magnitude-check detection rates. The 774/295 figures cover only the recorded payload set — [When Latent Agents Lie](https://arxiv.org/abs/2606.28958)
- MIRROR (arXiv 2610.02349, 1 Oct 2026; accepted at the NeurIPS 2026 Workshop on Foundations of Language Model Security). Replicates one canonicalised payload across k logical routes and accepts only on a strict-majority digest match; unkeyed hashing, so it authenticates nothing on its own and an on-path adversary controlling a majority of routes wins. Guarantee holds for route-compromise fraction α < 0.5; for correlated routes the binding quantity is the largest shared-failure group. Against Agent-in-the-Middle attacks on MMLU, HumanEval, MBPP across two frameworks and four topologies plus a MetaGPT deployment: attack success 0% below threshold at 1× LLM token cost; LLM-as-a-Judge costs 35× and blocks up to 44.2% of benign outputs. No latency or bandwidth figures; k not stated on the page — [MIRROR](https://arxiv.org/abs/2610.02349v1)
- "Attesting Outputs and Delegation Ancestry in Multi-Agent AI Systems" (arXiv 2608.30387, 31 Aug 2026, Liu and Yu, cs.CR; preprint). A trusted deployer runtime signs a hash of each released output; ancestry evidence records whether each cross-deployer delegation edge was authorised; three designs (signed linked list, Merkle chain, co-signed DAG). Verification is after an incident by an auditor. Overhead: ancestry-only checks 24.3-499.2 µs per hop (M1 Pro); local workflow 813.1 ms with evidence vs 770.8 ms without (about 42 ms); AWS three AZs issuance 3.651 ms, complete verification 5.015 ms excluding TLS, KMS and model serving. 30/30 local signed-DAG tasks verified; 1,000/1,000 AWS paths verified; a child-key-only claim rejected. The signed hash "does not prevent prompt injection"; single-signer designs admit an unauthorised parent binding after child-key compromise — [Attesting Outputs](https://arxiv.org/abs/2608.30387)
- "Verifiable Manifest Signing and Transparency Enforcement for Secure MCP-Based LLM Pipelines" (arXiv 2601.23132, v1 30 Jan 2026, v2 24 Jun 2026; preprint). Each MCP tool-use manifest is canonicalised, policy-validated, freshness-checked and signed; a fail-closed enforcement layer rejects non-compliant or stale manifests before execution and logs accepted invocations in a Merkle transparency log. Verification latency at most 9.4 ms on edge devices; up to 50,000 manifests with near-linear scaling (R² = 0.998); rejection above 98.7% for expired, malformed, replayed and policy-violating manifests; models GPT-5.3, LLaMA-3.5, DeepSeek-V3. Signature algorithm, threat model and key management are not in the abstract; tool *outputs* are not said to be signed — [Manifest Signing](https://arxiv.org/abs/2601.23132)
- A2A 1.0.0 (latest released): Task fields are id, contextId, status, artifacts, history, metadata; Message fields are messageId, contextId, taskId, role, parts, metadata, extensions, referenceTaskIds. Neither carries a signature, hash or verification field. Section 3.7: messages "MUST NOT be considered a reliable delivery mechanism for critical information". Section 8.4 "Agent Card Signing" and 4.4.7 "AgentCardSignature" exist in the table of contents (not read). Extensions are URIs listed in a Message's `extensions` field; a server may require one and return `ExtensionSupportRequiredError`. No verification or provenance extension is listed in the visible text — [A2A spec](https://a2a-protocol.org/latest/specification/)

Version naming conflicts: one guide says v1.0 stable April 2026, another that Google promoted A2A 1.2 to production at Cloud Next 22 Apr 2026 — [alicelabs guide](https://alicelabs.ai/en/insights/a2a-protocol-guide-2026); [cloudmagazin](https://www.cloudmagazin.com/en/2026/04/25/a2a-protocol-1-2-in-production-what-dach-cloud-architects-need-to-change-in-their-istio-setup-now/)
- Key-isolated threshold signing (arXiv 2609.05901) puts a reviewer-to-executor path behind threshold BLS signatures with quorum gating and message binding; snippet only — [arXiv 2609.05901](https://arxiv.org/abs/2609.05901)

### Inferences
- Every cryptographic scheme found binds *bytes* (payload digest, manifest, released output) to an *identity* (specialist, deployer, signer). None binds a claim to its truth. The HMAC manifest stops tampering in transit; it would pass a specialist that honestly sends a wrong KV cache.
- Overheads where measured are milliseconds (5-10 ms verification, about 42 ms end-to-end attestation) or zero extra LLM tokens (MIRROR), two orders of magnitude below any LLM-judge check (35× tokens). The cost argument against transport-level integrity is weak; the argument against it is that it checks the wrong thing.
- The latent channel's only measured defence has no overhead numbers at all, the largest reporting gap in this cluster given that it ships a full KV cache per message.

### Gaps
- No latency, bandwidth or compute figures for the HMAC manifest on KV caches; no quantified collapse under attack.
- A2A's Section 8.4 text was not read directly; details of Agent Card JWS come from secondary sources.
- No paper found secures activation- or hidden-state channels other than KV caches (Communicating Activations, C2C, LatentMAS in the background report have no integrity layer reported).

## Key question 5: What do the papers say remains open?

### Takeaway
The authors' own gaps line up with the brief's three: nobody gates each claim before broadcast inside a debate; nobody has compared a code-enforced fixed-field channel with free text; and nobody has separated the information cost of structure from its removal of the persuasion surface. The papers add: text labels do not survive summarisation, cryptographic integrity does not reach truth, and verification that is too strong or too late destabilises consensus.

### Cited Findings
- Tool-MAD: no limitations section; the only admitted constraint is cost ("prohibitively expensive" repeated trials); judge model unnamed — [Tool-MAD HTML](https://arxiv.org/html/2601.04742)
- PROClaim: 11× tokens, 0.790-0.950 variance across identical runs, rationales not faithful, sampled cross-domain evaluation, one model assignment — [PROClaim HTML](https://arxiv.org/html/2603.28488)
- Echoing: "structural scaffolds reduce echoing but do not eliminate it, so deeper architectural or training-level solutions may be needed"; turn-level mitigations and activation analysis left to future work; asymmetric design (22 customer models vs 3 seller configurations) — [Echoing HTML](https://arxiv.org/html/2511.09710)
- Bronder: does not show tool results have no effect, only that native placement "was not necessary" and carried no more weight than announced inline text; four-day drop from 14/24 to 7/24 unexplained — [Bronder](https://arxiv.org/abs/2608.14992)
- Hu: does not implement or validate the structured-state fix; only text repairs tested and found partial; lexical survival of a status word "does not guarantee the caution is preserved" — [Silence Is Endorsement HTML](https://arxiv.org/html/2609.20211)
- Brito and Baquero: full-KV latent memory is useful but "should be treated as a security-sensitive object"; no overhead reported — [When Latent Agents Lie](https://arxiv.org/abs/2606.28958)
- Trust boundaries: "proof validity is not factual truth"; guarantees assume independent credentials, honest signing, a trusted verifier and complete mediation; non-significant results are not evidence of equivalence — [Trust Boundaries](https://arxiv.org/html/2610.24298)
- MIRROR: nothing is authenticated; everything rests on an honest majority of routes; correlated route failure shrinks protection — [MIRROR](https://arxiv.org/abs/2610.02349v1)
- Pramana: LLM oracles make inference and analogy claims non-deterministic; pilot does not validate the protocol; SLA bound unmeasured — [Pramana](https://arxiv.org/abs/2605.20312)
- Grading the Narrators: the content critic (word overlap) is the binding constraint and an LLM-backed critic is needed; corroboration assumes independence that correlated models violate — [Grading the Narrators](https://arxiv.org/html/2607.24117)
- Provenance survey: open problems include claim-level semantic provenance, provenance-aware runtime safety and recovery, and realistic execution-trace benchmarks — [Provenance survey](https://arxiv.org/html/2606.04990v1)
- Delayed verification: Byzantine faults, edge-level correctors and directed pipelines are future work; placement validated only on a linear surrogate — [Delayed Verification](https://arxiv.org/html/2606.27409v1)
- Attestation: does not prevent prompt injection; the contribution is composition of standard primitives — [Attesting Outputs](https://arxiv.org/abs/2608.30387)

### Inferences
- The field has three disjoint toolkits: tool-grounded debate (checks evidence, LLM-scored, post-hoc), script gates (check artifacts, status, attribution, pre-propagation, outside debate) and cryptography (checks bytes and identity, millisecond cost). No paper composes the three, and the one place they would meet, a per-claim gate that runs a script on a structured field before the harness forwards the message, is not built anywhere found.
- The cleanest next experiment the literature itself points to is Hu's unbuilt fix plus Echoing's scaffold: carry verification status as a structured field the harness, not the model, sets, and measure both adoption (Bronder's metric) and task quality (TalkHier's metric) against free text at matched tokens.

### Gaps
- No OpenReview entries for 2026 venues were located for any of the core papers; venue status rests on arXiv comments (Echoing: ICLR workshop; MIRROR: NeurIPS 2026 FLMSec workshop; PROClaim: "under review"; contestable MAD: ICMR 2026 challenge submission).
- No paper measures information loss and persuasion-surface removal in the same ablation; TalkHier's −4.7 / −8.9 remains the only information-loss number and Echoing's 70% → under 10% the only behaviour number.
- No system found verifies each claim before broadcast within a multi-agent exchange; EviBound and ProvenanceGuard gate a single agent's output to a user or next stage, not a peer message.
