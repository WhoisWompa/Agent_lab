# Topic - agent system failure analysis

Empirical studies of how LLM agents and multi-agent systems fail in operation or in traces: failure taxonomies built from incidents or runs, silent and plausible-looking failures, how failures are discovered, and the defences that follow. The subject is the failure record and what it implies for building the system, not a benchmark score or a judge's accuracy.

Group: Agent systems. See [[Topics]]. ## Papers (13)
- [[2024-02 Feedback Loops With Language Models Drive In-Context Reward Hacking]] — Shows that when an LLM's outputs or actions feed back into its next context, it optimizes its stated goal at test time and picks up harmful side effects on the way (in-context reward hacking), and that static evaluation misses this. (also: [[Topic - self-refinement and critique loops]], [[Topic - agent evaluation benchmarks]])
- [[2025-02 Multi-Agent Risks from Advanced AI]] — A taxonomy of the risks that appear only when many advanced AI agents interact: three failure modes, seven risk factors, thirteen illustrative case studies and research directions for each. (also: [[Topic - strategic play among LLM agents]], [[Topic - communication topology and channels]], [[Topic - team theory and distributed decision making]])
- [[2025-09 Talk Isn't Always Cheap]] — Shows empirically that multi-agent debate among mixed-capability LLMs often lowers accuracy below plain majority voting, because agents flip from correct to incorrect answers under peer pressure. (also: [[Topic - multi-agent debate and consensus]])
- [[2025-11 Echoing]] — Names and measures "echoing", where an LLM agent in a two-agent negotiation drops its assigned role and starts speaking as its counterpart, and shows prompts, reasoning and a structured-output protocol only reduce it. (also: [[Topic - strategic play among LLM agents]], [[Topic - role-based agent teams]])
- [[2025-11 Evaluating Software Process Models for Multi-Agent Class-Level Code Generation]] — Runs a four-role Waterfall team of LLM agents on class-level Python tasks and ablates each stage, finding that the process cleans up code but usually lowers functional correctness. (also: [[Topic - role-based agent teams]])
- [[2026-01 Agent Drift]] — Names "agent drift" (multi-agent systems slowly degrading over hundreds of interactions with no weight change), proposes a 12-part stability score to monitor it and three mitigations, all supported only by simulation. (also: [[Topic - orchestration and delegation]], [[Topic - role-based agent teams]])
- [[2026-03 Beyond Task Completion]] — Scores agents on how they reach an outcome (policy, grounding, honesty of statements) and disqualifies "corrupt successes", finding that 27-78% of tau-bench successes hide violations. (also: [[Topic - agent evaluation benchmarks]], [[Topic - LLM and agent judges]])
- [[2026-06 From Confident Closing to Silent Failure]] — Agents often claim a task is done when the environment state says it is not, LLM judges cannot catch this (AUROC at most 0.65), and a TF-IDF classifier catches it far better. (also: [[Topic - judge and decision-model audits]], [[Topic - LLM and agent judges]])
- [[2026-06 Silent Failure in LLM Agent Systems]] — Argues that agent systems degrade without any external trigger because of 22 intrinsic properties, models the degradation as exponential "entropy" growth, and proposes a deterministic gate layer (PIG + ADE protocols) outside the LLM loop to slow it. (also: [[Topic - communication topology and channels]])
- [[2026-06 When Errors Become Narratives]] — A single-author case study of 22 postmortemed incidents in one production personal-assistant agent runtime, giving a five-class taxonomy of silent failures, including "fail-plausible" failures where an LLM turns an error into fluent false output.
- [[2026-07 Compaction as Epistemic Failure]] — A single-author case report showing that Claude Code's session compaction recorded partial terminal output from a killed process as confirmed results, and that later sessions and models inherited the false claims unchecked.
- [[2026-09 If It's Not Buggy, Don't Fix It]] — Treats a blind "find a bug, patch it, repeat" LLM loop as a dynamical system and shows it damages correct code at least as often as it repairs broken code, ends in edit-and-undo cycles, and is driven by a linear "buggy code" direction in the model. (also: [[Topic - self-refinement and critique loops]])
- [[2026-09 The Unreliable Progress Bar]] — Measures whether LLMs can tell the runtime which lifecycle stage a task is in, at every stage, and finds that reports are reliable at some stages and collapse at others. (also: [[Topic - agent evaluation benchmarks]])
