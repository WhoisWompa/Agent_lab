# Large Language Model based Multi-Agents: A Survey of Progress and Challenges

## One line
A survey that organises LLM-based multi-agent work along four axes (environment interface, agent profiling, communication, capability acquisition) and two application streams (problem solving, world simulation), then lists open challenges.

## Method
The problem: work on LLM multi-agent systems grew fast but independently, with no shared map of the field. The survey's answer is a schema that places every system on the same four dimensions (Fig. 2).

- **Agents-environment interface**: Sandbox (simulated, e.g. a code interpreter or game rules), Physical (robots), or None (e.g. pure debate, where only inter-agent talk matters).
- **Agent profiling**: how roles are set. Pre-defined by the designer, Model-Generated by an LLM, or Data-Derived from an existing dataset. Examples are CTO and programmer, proponent, opponent and judge, werewolf and seer.
- **Communication**: paradigm (Cooperative, Debate, Competitive), structure (Layered, Decentralized, Centralized, Shared Message Pool as in MetaGPT), and content (almost always text).
- **Capability acquisition**: feedback source (environment, other agents, humans, or none) and how agents adjust: Memory, Self-Evolution (changing goals, plans or weights from communication logs), and Dynamic Generation of new agents at run time.

Applications are sorted into problem solving (software development, embodied agents, science experiments, science debate) and world simulation (society, gaming, psychology, economy, recommender systems, policy making, disease spread). Table 1 tags about thirty studies on every axis; Table 2 lists the datasets they use. The survey also presents three open-source frameworks, MetaGPT (SOPs and assembly-line roles), CAMEL (inception prompting) and AutoGen (customisable agents programmed in language and code).

The main reading it offers: problem-solving systems are mostly cooperative or debate with layered or centralized structure and environment feedback, while simulations are mostly decentralized with agent-interaction feedback. This is a pattern read off Table 1, not a tested claim.

## Evaluated on
A survey runs no experiments. The evidence it offers is descriptive.
- Field growth: Fig. 1 counts papers per 3-month interval by category (the counts are only in the figure, not stated in text).
- Coverage: Table 1 tags the surveyed studies across the four axes; Table 2 lists benchmarks per domain (e.g. HumanEval, MBPP and SoftwareDev for coding; RoCoBench for robots; MMLU, GSM8K and StrategyQA for debate; Werewolf, Avalon and Welfare Diplomacy for games).
- Benefits of multi-agent over single-agent are asserted (specialised profiles plus interaction) with no head-to-head comparison in the survey itself. Cited gains, such as debate improving factuality across six tasks, are taken from the original papers.

## Limitations admitted by the authors
- Benchmarks are thin: Table 2 is "far from comprehensive", and Science Team experiments, economic analysis and disease simulation have no comprehensive benchmark, so progress there cannot be compared.
- Existing evaluations test single agents in narrow scenarios and miss emergent group behaviour, which is what multi-agent systems are for.
- Hallucination compounds: one agent's false statement can be accepted and spread by the others. The survey names this as unsolved.
- Cost: every agent is a large model (e.g. GPT-4), so resources grow with agent count. Coordination, communication and scaling laws for agent count are called open.
- Learning is isolated: Memory and Self-Evolution adjust agents one at a time and do not exploit collective intelligence. Training signals also depend on a reliable interactive environment that is hard to build for many tasks.
- Almost all work is text-only; multi-modal settings are largely unexplored.
- Role-playing ability of LLMs "may have limitations" for simulation; this is stated without evidence.

## What it leaves untried
- No cross-system comparison of structures (layered vs decentralized vs centralized) on a common task, so the survey cannot say which communication structure suits which job. Table 1 only lists who uses what.
- No treatment of failure modes inside teams (role drift, conformity, wasted rounds, cost per solved task), although it calls hallucination cascades a challenge. Failure and efficiency evidence is what a builder would need.
- Game theory appears only as a simulation use (Prisoner's Dilemma, Werewolf, Diplomacy); incentives, aggregation of agent outputs and orchestration as a formal design problem are not analysed.
