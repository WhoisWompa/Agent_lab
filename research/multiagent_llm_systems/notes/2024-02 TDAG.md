# TDAG: A Multi-Agent Framework based on Dynamic Task Decomposition and Agent Generation

## One line
A main agent splits a task into subtasks, rewrites the remaining subtasks as earlier ones succeed or fail, and has an LLM generate a tailored subagent (tool document plus retrieved skills) for each, alongside a travel-planning benchmark that gives partial credit.

## Method
The paper attacks two weaknesses of decompose-then-execute agents. First, error propagation: once the plan is fixed, one failed early subtask makes later ones unexecutable. Second, hand-built subagents do not generalise across tasks.

TDAG has a main agent that decomposes the task T into subtasks. Subtask i runs in its own subagent, which sees the subtasks so far and the earlier results, not the whole raw history. This keeps irrelevant context out of each call. After each subtask the main agent updates the remaining list from the results (for example, "find earlier transportation options" after a time-limit failure). The plan is therefore a living list, not a fixed one.

Each subagent is generated per subtask by LLM prompting, in two parts:
- **Tool document rewriting.** The raw tool documentation is restructured and clarified, because redundant or unclear docs mislead the agent.
- **Incremental skill library.** After a successful subtask the subagent summarises its solution as a skill (name, detail, solution). A SentenceBERT retriever supplies the most relevant skills to later subagents, and a dedicated agent refines existing skills. The paper notes that, unlike Voyager, skill correctness cannot be checked against the environment, so skills are refined continuously rather than trusted.

The benchmark, ItineraryBench, has 364 travel-planning test samples. A simulator executes the plan, so no single ground truth is needed. Scoring is tiered: 60 points for executability, 20 for constraint satisfaction, 20 for time and cost efficiency. A higher tier is scored only after the lower one is fully met. The argument is that binary success hides partial progress.

## Evaluated on
- **TDAG beats all four baselines (ReAct, Plan-and-Solve, Plan-and-Execute, ADAPT) on ItineraryBench.** Average 49.08 vs 44.74 for ADAPT and 43.02 for ReAct, with GPT-3.5-turbo-16k.
- **Both components matter.** Removing agent generation gives 46.69 and removing dynamic decomposition gives 46.23 on the average.
- **A fixed plan can be worse than no decomposition.** Plan-and-Execute (42.85) does not beat single-agent ReAct (43.02). Cascading task failure is the error type TDAG avoids: 4.35% of all such errors against 34.78% for P&E and 32.61% for ReAct.
- **Binary scoring cannot separate methods on hard tasks.** The authors say it fails to distinguish methods when completion is rare, while the fine-grained score does. The numbers are only in a figure, not the text.
- **It transfers to other environments.** TextCraft success 73.5 vs 52.0 for ADAPT. WebShop reward 64.5 vs 60.0 and success 45 vs 44. Agent generation was switched off here and ADAPT's predefined agents were used, so only dynamic decomposition is tested.

## Limitations admitted by the authors
- ReAct makes fewer external-information errors than TDAG (17.32% vs 19.33% of that error type). The authors guess that complex methods produce excess context that invites hallucination, but they do not test it.
- Skill correctness cannot be verified in this environment, so a wrong skill can enter the library and be retrieved. The only safeguards are continuous refinement and a duplicate filter, and no measurement of skill quality is given.
- Agent generation could not be used on WebShop or TextCraft because there is no tool document and the tasks are monotonous. The WebShop gain is therefore one point of success rate, which does not isolate agent generation.

## What it leaves untried
- Every result uses GPT-3.5 variants. It is untested whether the gain survives with stronger models, which may already avoid early errors, so the benefit of re-planning is unknown there.
- No cost or latency accounting. Per-subtask agent generation, tool-doc rewriting and plan updates add LLM calls, and the paper does not report what the 4.3-point average gain over ADAPT costs.
- No test of the skill library alone, and no check of whether it grows noisy over many tasks. The ablations remove only agent generation as a whole.
