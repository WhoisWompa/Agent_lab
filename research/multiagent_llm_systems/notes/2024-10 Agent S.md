# Agent S: An Open Agentic Framework That Uses Computers Like a Human

## One line
A Manager-Worker GUI agent that plans with web search plus retrieved past experience and acts through a bounded, language-level interface, reaching 20.58% on OSWorld against 11.21% for the best baseline.

## Method
The paper targets three problems of desktop-control agents: missing and outdated application knowledge, long multi-step tasks, and noisy, non-uniform interfaces.

- **Manager (planner).** It rewrites the task as a "How to do X" query. It runs that query against an online search engine and against its Narrative Memory, which holds summaries of earlier whole tasks, successful and failed, with the concrete actions stripped out. An LLM fuses the two into one guideline. It then emits an ordered queue of subtasks, each with context.
- **Workers (executors).** Each subtask goes to a Worker. The Worker retrieves matching entries from Episodic Memory, which holds step-level plans with grounded actions from subtasks that finished. A Trajectory Reflector watches the episode and advises against repeated actions. The Worker emits one structured step per turn: status check, observation analysis, next action. It ends the subtask with DONE. A FAIL resets the hierarchy and the Manager replans from the current screen state.
- **Self-Evaluator.** It turns finished subtasks and tasks into short textual summaries and writes them back into the two memories. The paper likens this to hierarchical reinforcement learning with retrieval as the learning step. It uses no human or environment feedback.
- **Memory bootstrapping.** The memories are seeded by running the agent on generated exploration tasks, including tasks generated from the benchmarks' own initial environments. After that they keep updating during inference.
- **Agent-Computer Interface.** The agent sees a screenshot and an accessibility tree. The tree is augmented with OCR text blocks missing from it, and every element gets an integer ID. Actions are a small set of primitives (click, type, hotkey) that take element IDs. Only one action is allowed per step, so each action yields immediate feedback. The reasons given: models have no internal coordinate system, and free-form code actions are unsafe and give no per-step feedback.

## Evaluated on
- **Beats the OSWorld baseline.** 20.58% with GPT-4o against 11.21% for the best GPT-4o baseline on all 369 tasks. Claude-3.5 reaches 20.48%. The largest gains are in Daily (27.06% against 12.33%) and Professional (36.73% against 14.29%). The authors attribute this to knowledge-heavy tasks benefiting from retrieval.
- **Web knowledge matters most.** On a 65-task subset, full Agent S scores 26.15%. Removing web knowledge gives 16.80%, removing episodic memory 18.46%, removing narrative memory 21.41%, and removing all three 13.85%.
- **ACI and planning each contribute.** The baseline scores 10.77%. ACI alone gives 12.31%, ACI plus retrieval without hierarchical planning gives 20.00%, and the full system gives 26.15%. Retrieval on the baseline adds little (12.31%), so the interface and the experience work together.
- **Memory pipeline ablations.** Without exploration the score is 15.38%. Without the Self-Evaluator, storing raw trajectories, it is 18.46%. Without continual update it is 23.18%.
- **Transfers to Windows unchanged.** On WindowsAgentArena, 18.2% against 13.3% for NAVI, with no adaptation.

## Limitations admitted by the authors
- Steps and wall-clock time are not measured by this work or by prior work. The gains are therefore not shown to be efficient, and the authors suggest evaluating time-accuracy trade-offs.
- Only closed frontier models (GPT-4o, Claude-3.5) are used. Whether the design helps smaller open MLLMs is untested.
- Failures remain common. In the 65-task subset, execution errors appear in 79.59% of failed tasks, grounding errors in 53.06%, and planning errors in 34.69%. The Subtask Failure Rate is 57.17%. The planner is therefore not the main bottleneck. Errors include repeated actions, drifting from the subtask, and combining several actions into one, which breaks the one-action rule.
- Absolute success stays low at about 21%, and Office tasks are weak (13.00 to 13.83%). On WindowsAgentArena, Office scores 0.0 and Web Browser is below NAVI (13.3 against 20.0).

## What it leaves untried
- No test of multi-run behavior. Memory is seeded by exploration on tasks derived from the test benchmarks' own environments, and the paper does not check that this leaks no benchmark-specific information. Exploration is the largest single memory effect (26.15% down to 15.38%).
- Ablations use a 65-task subset, with only 6 to 17 tasks per category. Single-category changes of a few points are within what a handful of tasks can move. Results on the full set are given only for the final system.
- Feedback from the Worker to the Manager is only DONE or FAIL plus replanning. A richer signal, such as which step failed, is not tried. Execution errors dominate failures, so this is where gains are likely.
