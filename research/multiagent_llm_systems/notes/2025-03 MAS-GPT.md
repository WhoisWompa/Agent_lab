# MAS-GPT: Training LLMs to Build LLM-based Multi-Agent Systems

## One line
A 32B model is fine-tuned to write, in one inference, a query-specific multi-agent system as Python code, replacing hand-built teams and multi-call search for a team.

## Method
Problem: hand-built teams (MetaGPT, ChatDev, AgentVerse) are fixed regardless of the query, and adaptive methods (GPTSwarm, DyLAN, ADAS, AFlow) move the human effort into compute, needing over 10 LLM calls with long context to get a team for one query.

Idea: treat "build the team" as a text-generation task. The input is a user query and the output is an executable MAS. Every MAS is written as one Python `forward(query)` function. Agent prompts are variables, LLM calls are function calls and agent-to-agent links are string concatenation. The generated function is then run on the query to produce the answer.

Since base LLMs know nothing about this task, the contribution is the training data, built so that the model can learn a clear query-to-MAS mapping:
- Start from a pool of 40+ MAS designs (re-implemented debate, self-consistency, self-refine, plus hand-made ones). Run every query against every design and keep the pairs whose answer is correct.
- Inter-consistency: cluster similar queries and give each cluster the single design with the highest summed score. Without this, similar queries map to many different designs and the model has no consistent target.
- Intra-consistency: a strong LLM rewrites the chosen design to fit the query (a physics question should not get a biology expert) and writes a short reasoning for why. The rewrite is kept only if its score is not worse than the original.
- Fine-tune Qwen2.5-Coder-32B-Instruct on about 11k (query, reasoning plus code) pairs, with Llama-3-70B driving the MAS during data building.

The assumption is that correct execution on a training query shows the design suits that query type, and that this transfers to unseen queries.

## Evaluated on
- Beats 10 baselines on average over 8 benchmarks with Llama-3-70B driving the MAS: 65.47 against 61.58 for the next best (self-consistency). The gain is concentrated: GSM-Hard 62.40 against under 48 for any baseline, MATH 68.65 against 61.59. Most other columns are within about 1 to 2 points of the best baseline.
- Holds on out-of-domain benchmarks (GPQA, SciBench, HumanEval): best on GPQA (24.21 against 21.05 for a single LLM) but not on SciBench (37.62 against 40.19 for AgentVerse). Across other driver LLMs the margin is small: 74.46 against DyLAN's 74.33 with Qwen2.5-72B; 70.50 against 69.29 with GPT-4o-mini.
- Lifts strong reasoning models on AIME-2024: o1-preview 53.3 to 66.7, DeepSeek-R1 80.0 to 90.0 (a 30-problem set, so each problem is 3.3 points).
- Beats AFlow, a method optimized on MATH, by 3.53 points on MATH. AFlow's MAS falls below a single LLM on the other domains. AFlow costs about 10 Claude-3.5-Sonnet calls per query against one 32B inference here.
- The data design matters: random choice among correct MAS instead of cluster-level selection drops MATH from 68.65 to 60.26. Dropping the rewrite gives 66.23, dropping the reasoning gives 64.90.
- Scaling: with zero training data the base model cannot produce an effective MAS. More data gives fewer execution failures and better accuracy. 7B to 14B to 32B improves steadily (read from a figure, no numbers).

## Limitations admitted by the authors
The paper has no limitations section. The only stated caveat is that training costs something, which it argues is a one-time expense against unbounded inference.

## What it leaves untried
- Training signal is only SFT on correct-answer pairs from a fixed pool of 40+ designs. Reinforcement learning on the executed MAS result is not tried, and the model cannot learn designs better than what the pool and the rewriter supply.
- Training queries come only from math, coding and general QA with verifiable answers. Open-ended tasks without a ground-truth check, where the pair-scoring step cannot run, are not tested.
- Cost is counted in LLM calls, with MAS-GPT scored as 0.5 of a 70B call from size alone. Latency, tokens and the one-time training bill are not compared, and the claim that adaptivity is worth it is not tested against simply choosing the best fixed design per domain.
