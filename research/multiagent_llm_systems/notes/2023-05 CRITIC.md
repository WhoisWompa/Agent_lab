# CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing

## One line
A frozen LLM drafts an answer, checks it against external tools (web search, a Python interpreter, a toxicity API), and rewrites it from the tool-grounded critique, because the same LLM cannot reliably check itself.

## Method
The problem: LLMs hallucinate facts, write flawed code and produce toxic text, and fixing this by training needs large human annotation. Earlier self-correction loops (Self-Refine, Reflexion, RCI) let the model judge its own output, but the model has no reliable signal for what it got wrong.

The idea is a verify-then-correct loop around a black-box model, with the verification step grounded in a tool. The model writes an initial answer, then writes critiques while calling tools through text-to-text APIs. It issues a search query and reads the evidence, runs its code and reads the error or result, or reads a toxicity score. The tool output is pasted into the critique, and the model produces a revised answer conditioned on the question, the old answer and the critique. This repeats until the critique says the answer is correct, the answer stops changing for two rounds, toxicity falls under 10%, or a cap of 3 to 4 rounds is hit.

Nothing is trained. The only requirement is a few-shot, ReAct-style demonstration per task and a tool that accepts and returns text. The tool is chosen per task by the authors; automatic tool selection is described as possible but not used. The critique checks named aspects, such as plausibility (is a negative number of pizza slices sensible?) and truthfulness (does the search evidence support the claim?). The authors argue the tool gives credible grounding and actionable suggestions, which plain re-sampling does not.

## Evaluated on
- Tool feedback carries the gain, not self-critique. On question answering with ChatGPT, removing the search tool leaves F1 near the chain-of-thought start. The model's own critiques add -0.03 and +2.33 F1 across the two OpenAI models, against +5.6 and +7.7 F1 for the full method.
- Beats retrieval-only and voting baselines on three QA sets. With ChatGPT it beats ReAct by 5.1 F1 on average over the datasets, and it beats self-consistency on most columns. It does not beat rejection sampling on TriviaQA (ChatGPT EM 75.1 vs 82.0).
- Code execution helps math, and more for stronger models. On TabMWP with LLaMA-2-70B it adds 16 points over program-of-thought. Without the interpreter, text-davinci-003 loses 1.8 points on GSM8k. Gains grow with model size (+4.7, +9.4, +16.0 on TabMWP at 7B, 13B and 70B).
- Detoxification matches trained methods without training. ChatGPT's maximum toxicity falls from 0.325 to 0.173, close to Quark (0.196) and the trained Self-Correct (0.171), with fluency and diversity kept. Without the API, the LLM judging toxicity itself leaves it at 0.339.
- LLMs are poor self-verifiers. Self-evaluation gets 54% accuracy verifying HotpotQA answers and is below an always-say-correct baseline on TriviaQA. With tools, accuracy is 76.5% and AUROC 0.831 on HotpotQA.
- Most of the gain arrives in 2 to 3 rounds. Hallucinations on 100 HotpotQA cases drop from 36% to 7%.

## Limitations admitted by the authors
- Latency grows linearly with rounds. Two corrections on math cost about twice the baseline time, plus tool calls. One round already gives much of the benefit, which is the authors' mitigation.
- It depends on hand-written few-shot demonstrations, and different prompt constructions change the results. These demonstrations also lengthen the context.
- It may not transfer. Whether it works on other tasks and models is "uncertain", because the model may not need, or be able to use, external feedback. Only text was tested.
- Where the tool gives no reliable signal, correction is weak. Intrinsic reasoning errors on GSM8k are fixed only 26.7% of the time, against 57.4% for unreasonable outputs.
- The loop sometimes breaks correct answers. On GSM8k, accuracy on originally correct programs falls 4.3%, so 14.3% of remaining errors are wrong corrections. On HotpotQA, 10% of CRITIC's errors are wrong corrections and 12% are refusals when no evidence is found. The authors call refusal expected behaviour.
- The tools can carry bias or errors. The authors note this as an ethical concern but do not measure it.

## What it leaves untried
- No learned or automatic choice of tool per input. Tools are fixed per task, so the claim of a general framework rests on three hand-picked pairings.
- The "oracle" variant corrects only wrong answers and scores far higher (ChatGPT AmbigNQ F1 79.9 against 74.9). The paper does not build a trained or calibrated trigger to close that gap, nor does it stop the 4.3% damage to correct answers.
- No comparison of cost against sampling at equal compute. Rejection sampling beats it on TriviaQA, and the paper does not match the compute of the two.
