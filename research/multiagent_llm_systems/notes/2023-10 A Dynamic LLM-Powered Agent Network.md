# A Dynamic LLM-Powered Agent Network for Task-Oriented Agent Collaboration

## One line
DyLAN first picks the most useful agents from a candidate pool with an unsupervised peer-rating score, then lets that team collaborate layer by layer, dropping weak agents and stopping early when two thirds agree.

## Method
Problem: most multi-agent systems (debate, CAMEL, AgentVerse, Reflexion) use a fixed set of agents and a fixed communication structure, and the agents' roles are written by hand or generated by an LLM without checking that they help. Weak or off-domain agents interfere with the rest of the team.

Idea: model collaboration as a temporal feed-forward network (T-FFN). Each layer is a time step, each node an agent, each edge a message from one step to the next. Two stages run on it.

- Task solving. At every step each active agent reads all responses from the previous step and answers. A separate LLM "ranker" ranks the responses, and only the top-ranked agents continue, so the communication graph shrinks as the query proceeds (agent team reformation). Inference stops early when more than 2/3 of the agents in one layer give the same answer, borrowing the 3p+1 bound from Byzantine consensus, or at a maximum step.
- Team optimization. Run one preliminary trial of the above on the task. Each node rates its predecessors' answers (peer rating). Contributions are then propagated backward from the last layer: a node's contribution is the sum of its successors' contributions weighted by the rating they gave it. Summed over all layers, this is the Agent Importance Score, and the top-k agents form the team. The score is unsupervised, needs no labels, and sums to 1 per layer. One trial's scores can be reused for several selections.

Why it should work: an agent's actual behaviour in a trial is a better signal than its role description, and back-propagating ratings credits agents whose answers later agents relied on.

## Evaluated on
All with GPT-3.5-class backbones, cost counted in API calls.
- Code generation (HumanEval): Pass@1 82.9 against 73.2 for a single run, 75.0 for AgentVerse and 81.1 for LATS, at 16.85 calls versus 48 for LATS.
- Decision-making (WebShop): reward 68.3 against 50.6 for direct execution and 66.0 for BOLAA, at 24.85 calls versus over 400 for LATS.
- Reasoning: MMLU 70.5 versus 69.3 for LLM Debate with 4.39 calls versus 12. MATH 35.7 versus 32.4 for debate, with fewer calls (7.15 versus 8). The MATH gain is smaller than on other tasks, which the authors attribute to MATH's heavy knowledge dependence (a guess, not tested).
- Team optimization helps: selected teams gain up to 25.0 points on a single MMLU subject (college mathematics 40.0 to 65.0, Mathematician and Programmer selected). Cutting 7 candidates to 3 beats 4-agent debate and cuts calls by about half. On WebShop, 8 agents to 4 lifts reward from 53.0 to 68.3.
- Ablations: early stopping cuts calls by 11.3% to 66.2% depending on task with little accuracy change. Removing team reformation costs accuracy everywhere, for example HumanEval 82.9 to 76.2.
- Backbone stability: on code, DyLAN stays high across two backbones while Reflexion and CodeT swing with the backbone.

## Limitations admitted by the authors
- Gains shrink when no candidate fits the domain. On MMLU "public relations" the gain is only 4.5 points, since none of the role prompts matches it.
- Early stopping works poorly for open-ended outputs. Code and web actions differ in format, so the 2/3 agreement check (BLEU 0.9) rarely fires. Savings are 11.3% on code against 66.2% on MMLU.
- Only closed GPT models were tested. The authors list open-source backbones as future work.
- Reviewers matter more than writers in the code team, so the selected team's balance still affects results. Pass@1 falls from 81.1 to 77.4 when reviewers drop from 3 to 2.

## What it leaves untried
- Open-source foundation models as agents and ranker. All results depend on the ranker's and raters' judgment, and the paper does not measure how reliable those LLM ratings are (unsupported either way).
- Running the optimization at larger candidate pools or with learned roles. Pools tried are 4 to 12 agents, and the cost of the preliminary trial is excluded from the reported call counts, so the true cost is not reported in the headline numbers.
- Tasks where roles must be complementary rather than interchangeable. On MATH all agents share one prompt, because preliminary tests with domain experts showed no significant gain, so selection is untested there.
