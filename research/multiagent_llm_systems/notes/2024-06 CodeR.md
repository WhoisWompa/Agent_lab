# CodeR: Issue Resolving with Multi-Agent and Task Graphs

## One line
Five role-specialised LLM agents resolve GitHub issues by executing a human-written plan stored as a JSON task graph, which the code follows strictly instead of asking the model to remember it.

## Method
The paper attacks three failure modes it names for multi-agent systems: free-form chat can loop without terminating, information is lost when one agent hands over to another, and plans written as prompt text are hard for models to follow. Its evidence for these is citation, not measurement in this paper.

The fix has two parts. First, roles: a Manager, Reproducer, Fault Localizer, Editor and Verifier. Each gets only the actions its job needs (for example only the Manager can plan and submit), so each next-step decision is chosen from fewer candidate actions. Each runs a ReAct loop on its own sub-task.

Second, the task graph. A plan is JSON: an entry agent, the agents involved, each agent's sub-task text, and a "downstream" field naming who runs next on success or failure. The harness parses the graph and activates the agents in that order, passing a summary report of each agent's actions to the next. Plans can be added or changed without touching agent code. The Manager only selects one of the predefined plans (the prompt forbids inventing one), reads the final summary, and then submits, re-plans or gives up. Four plans exist; only A (reproduce, localize, edit, verify, no loop) and B (edit directly, for simple issues) are used in experiments, to save cost.

A further idea is fault localization that mixes two signals. The Reproducer writes a failing test, whose coverage gives a spectrum-based (Ochiai) suspiciousness score. That is linearly combined with a BM25 text match between the issue and the code (lambda = 0.99 chosen). The paper's reason: both scores tie often (statements with equal coverage, statements in the same file), so each breaks the other's ties. Without a reproduced test with non-empty coverage, the spectrum signal is skipped.

## Evaluated on
- Best single-attempt result on SWE-bench Lite: 28.33% (85 of 300) reported, 27.33% (82) in the authors' re-run environment. Aider scores 26.33% reported, SWE-agent with GPT-4 18.00%. The text says "84 of 300" in one place, which does not match 85.
- Gain over SWE-agent + GPT-4 is 10.33 points. The authors credit pre-planning over on-the-go decisions, but no experiment separates planning from the other changes (roles, actions, fault localization).
- Ablation on 50 issues: removing multi-agent and task graph drops resolution from 22% to 10% (11 to 5 issues). Removing fault localization gives 14% (7 issues).
- Combining the two localization signals raises function-level top-1 precision from 6.63% (coverage alone) to 16.49 to 18.42%, and from 12.27% (BM25 alone), on 104 reproducible issues.
- Cost: 30.39 average requests and about $3.09 per issue, against 21.55 and $2.51 for SWE-agent + GPT-4.

## Limitations admitted by the authors
- Plans are human-authored expert experience, and only two of the four plans were tested. Coverage of issue types depends on a plan library the authors say they still must build.
- Spectrum-based localization needs a failing test. Where the Reproducer cannot produce one, or coverage cannot be collected (for example CLI-invoking scripts), only BM25 is used. Only 140 of 300 issues were reproduced, and 104 had usable coverage.
- The evaluation environment is not consistent across systems. The authors re-ran baselines in an adapted environment, and astropy and requests still hit container crashes that force restarts.
- More roles and actions raise requests and cost, which the paper calls an "acceptable rate".

## What it leaves untried
- Letting the Manager build or edit plans, or learning them. Selection among fixed plans is the entire planning ability, and the paper gives no number on how often the Manager picks the wrong plan.
- An ablation separating the task graph from the role split. The 22% to 10% drop removes both together, so it does not show which one matters.
- The loop plans (C, D) and the broader benchmark. All numbers are on SWE-bench Lite, mostly with the loop-free plan and one model (GPT-4 preview).
