# HALO: Hierarchical Autonomous Logic-Oriented Orchestration for Multi-Agent LLM Systems

## One line
HALO stacks a planner, a role-designer and role-specific workers, and uses Monte Carlo Tree Search over the workers' outputs to pick the reasoning path, reporting 78.6% average accuracy on HumanEval, MMLU and MATH against 64.0% for the best baseline.

## Method
The problem: existing multi-agent systems use hand-written role sets and fixed communication graphs, so they do badly on specialised, expert-level questions. Users also write loose prompts that agents misread. The paper offers no measurement of how often either failure happens. Its argument is only that the baselines' structure is static.

HALO has three stages.
- **Adaptive Prompt Refinement.** Four chained agents turn the raw query into a final prompt. They parse it into task type, intent and key details, draft a template, add slow-thinking strategies (chain-of-thought and similar) and tool-call instructions, then synthesise the final prompt. The parsed triplet is passed to every later agent as shared context.
- **Hierarchical Reasoning Stack.** A planning agent emits one subtask at a time and sees the history of earlier subtasks. For each subtask, a role-design agent invents the worker roles it needs (for a clinical question: Medical Researcher, Clinical Data Analyst, Endocrinology Expert) and writes each one's system prompt. The workers then run the subtask. Splitting planning, role design and inference is meant to avoid the "cognitive overload" of one agent doing all three, as in ReAct.
- **Workflow Search Engine.** Each role-specific agent is a node in an MCTS tree. A judging agent labels each output success, fail or continue. A scoring agent gives it a score in [0, 1]. The label shifts the score as a reward or penalty and backpropagates up the path. UCT then picks which agent to expand. The top-scoring agent at each step continues and failing branches are pruned.

Early stopping is borrowed from Byzantine fault tolerance. The loop ends when at least 66% of completed subtasks agree on an answer, or at the subtask budget. The 3p+1 result is cited as the motivation, but the paper does not show that it applies to LLM agents that share one underlying model.

The reward signal is an LLM judge and an LLM scorer. Nothing in the text checks how well their scores track correctness.

## Evaluated on
All runs use GPT-4o, and the numbers are averages over three runs.
- **Beats every baseline on all three benchmarks.** Average 78.6% vs 64.0% for ADAS, the strongest baseline. By benchmark: HumanEval 95.2 vs 82.4, MMLU 81.6 vs 72.8, MATH 58.9 vs 36.9. Against single-agent ReAct the average is 78.6 vs 52.0.
- **Gains are larger on hard subjects.** On five MMLU subjects (abstract algebra, college physics, formal logic, high-school maths, moral scenarios) HALO averages 70.8% vs 56.4% for ADAS. On MATH geometry, algebra and precalculus it averages 43.9% vs 24.4%.
- **Prompt refinement matters.** Removing it costs 5.3% on average, the largest drop being MMLU, 81.6 to 75.4.
- **Planning matters more.** Removing the planning agent and treating the refined prompt as one task costs 11.3% on average: HumanEval 95.2 to 83.8, MATH 58.9 to 44.7.
- **Reporting is inconsistent.** The abstract says "14.4% average improvement" but the table gap is 14.6 points. It also uses 13.3% for Moral Scenarios and 19.6% for Algebra. The reader cannot tell whether these are relative gains or point gaps.

## Limitations admitted by the authors
- The paper has no limitations section. The conclusion says only that long-term memory and external knowledge could improve results further. This is stated without evidence.
- The authors note they worked alone with no institutional support. This may explain the narrow evaluation, but they do not say so.

## What it leaves untried
- **No ablation of the search engine.** Only prompt refinement and planning are removed. MCTS is the headline idea but is never compared with a plain multi-sample or best-of-n vote at equal compute, so the search's contribution is unsupported.
- **No cost or latency report.** Each node needs a worker call plus a judge call plus a scorer call, with simulation rollouts on top, yet token cost, calls per question and wall-clock time are not given. The comparison with baselines is therefore not compute-matched.
- **One backbone and three benchmarks.** Everything uses GPT-4o. Baselines were run under the same few-shot setting, but HALO alone had code-interpreter tools for HumanEval. Baselines were not retuned with the same refinement, so the gain cannot be assigned to structure rather than extra prompt engineering.
