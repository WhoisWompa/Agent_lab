# Multi-agent LLM systems: empirical failure studies (A) and production frameworks (B), 2023 to Oct 2026

Reading lens tags used throughout (for the contract-theory / information-design / cheap-talk reader):
- **[TRUST]** one agent accepts another agent's (or a tool record's) unverified claim (cheap talk)
- **[FALSE-DONE]** an agent declares completion falsely or terminates prematurely
- **[NO-VERIFY]** verification skipped, superficial, or wrong (effort flows to what is checked)
- **[ROLE]** role or specification violation, drift, echoing
- **[HANDOFF]** information lost at a handoff, summary, compaction or context boundary (information design)

## Q1. Across the failure studies, what fraction of failures is attributed to inter-agent misalignment and verification problems versus the task itself?

### Takeaway
In MAST, the central taxonomy, failures attributed to system design / specification account for about 44%, inter-agent misalignment about 32%, and task verification about 24% (sums of the v3 per-mode figures). None of the 14 modes is "the task was too hard". Verification failures (no/incomplete + incorrect verification) alone are 17.3%, and completion-related failures (unaware of termination + premature termination) are 18.6%. Later work finds the same pattern from other directions. False success (claimed completion that does not match the system state) is 45-48% of failures in single-control tau2-bench domains, 75.8% on AppWorld, and only 3% where an independent party can check the state. Attribution (finding which agent caused a failure) is itself unsolved: best agent-level accuracy is 53.5%, step-level 14.2%.

### Inferences
- Under MAST, the share of failures that are not about the model's raw task ability is effectively 100% by construction: there is no "task too hard" category. Inter-agent misalignment plus verification is about 56% (32.35 + 23.5). Spec/role violations plus termination misjudgment (FM-1.1, 1.2, 1.5, 3.1) are about 32%.
- Counting by lens: [NO-VERIFY] 17.3%, [FALSE-DONE] 18.6%, [ROLE] 20.7% (FM-1.1 + 1.2 + 2.3), [HANDOFF] 5.85%, explicit [TRUST]-type (fail to ask for clarification, ignored input) 8.7%. Handoff loss is small in MAST's count but large in Laban et al. (39%). The likely reason: MAST's frameworks mostly share a group-chat transcript, so little is lost at handoff by design.
- The 2026 false-success results fit a contract-theory reading closely. Where the principal (user simulator) can observe state, false completion falls from ~48% to 3%; LLM judges reading only the narrative cannot separate true from false claims (AUROC ≤ 0.65). Bronder's result suggests that the label "unchecked" on a record does not discount it.

## Q2. Do any compute-matched comparisons show multi-agent beating single-agent, and in which conditions?

### Takeaway
Yes, but only on decomposable, parallelizable tasks, and only while the single agent is still weak. Kim et al. (260 configurations, token-budget-matched) find +80.8% for centralized multi-agent on Finance Agent and up to -70% on sequential planning (PlanCraft). Added agents hurt once single-agent accuracy exceeds about 45%. On multi-hop reasoning under equal thinking tokens, single agents match or beat MAS (Tran & Kiela 2026). Earlier "more agents" gains (voting, MoA) are largely explained by more samples, not more roles: Self-MoA beats mixed MoA, and the gain from call count is non-monotone.

### Inferences
- The conditions under which MAS wins are consistent across sources: breadth-first, decomposable work (financial sub-analyses, broad research), a centralized aggregator that checks results, and a weak single-agent baseline (<~45%). Anthropic's 90.2% is in the same regime (breadth-first research) but is not budget-matched; its own finding that token usage explains 80% of variance is consistent with Tran & Kiela's "unaccounted computation".
- Sequential, tightly coupled tasks (planning, SWE) lose with MAS, which matches the Data Processing Inequality / handoff-loss argument.
- "More agents" results are about sampling, not coordination; once sampled agents talk to each other (debate), conformity effects (Wynn et al.) can make accuracy fall over rounds.

### Gaps
- No compute-matched study found for full role-based teams (ChatDev/MetaGPT style) vs one agent on the same budget; MAST does not compare against a single agent.
- Kim et al.'s raw per-model numbers and statistical significance by benchmark were not fully read (HTML truncated after 100k chars).
- Tran & Kiela's exact accuracy deltas are not in the abstract.

## Q3. Which frameworks enforce termination in code, and which rely on an agent saying it is done?

### Takeaway
Every major framework has a hard code-level cap (max messages/turns/steps/iterations/recursion). The semantic decision to stop, though, almost always rests on an agent's own signal: a "TERMINATE"/"APPROVE" text mention, a final_answer tool call, an escalate/exit_loop tool, an output with no tool calls, or the lead agent "judging" it has enough. Built-in verification of a sub-agent's result before it is accepted exists only as optional hooks: smolagents `final_answer_checks`, CrewAI task guardrails (retry up to 3), OpenAI SDK output guardrails, and AutoGen `FunctionalTermination`. None is on by default. A2A's task state machine lets a remote agent mark itself COMPLETED with no protocol-level check.

### Cited Findings

**AutoGen (Microsoft) AgentChat v0.4+ and AG2**
- Paper: Wu et al., "AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation", arXiv 2308.08155 (COLM 2024 per my prior knowledge). PDF: https://arxiv.org/pdf/2308.08155 — [arXiv](https://arxiv.org/abs/2308.08155)
- Termination conditions (code): MaxMessageTermination, TextMentionTermination, TokenUsageTermination, TimeoutTermination, HandoffTermination, SourceMatchTermination, ExternalTermination, StopMessageTermination, TextMessageTermination, FunctionCallTermination, FunctionalTermination, composable with `|` and `&`. In group chats (RoundRobin, Selector, Swarm) the condition is checked after each agent response. TokenUsageTermination only works if agents report usage — [AutoGen docs: termination](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html)
- Lens: TextMentionTermination ("TERMINATE"/"APPROVE") is a self-declaration of completion [FALSE-DONE]. MAST's FM-1.5 (12.4%) and FM-3.1 (6.2%) were measured on AG2/MathChat among others — [MAST v3](https://arxiv.org/html/2503.13657v3)
- AG2 human_input_mode: ALWAYS (human input is the agent's reply), TERMINATE (asks a human only when terminating), NEVER — [AG2 docs: human in the loop](https://docs.ag2.ai/latest/docs/user-guide/basic-concepts/human-in-the-loop/)
- Status: Microsoft Agent Framework is documented as the direct successor of AutoGen and Semantic Kernel, with graph workflows, checkpointing and request/response human-in-the-loop; public preview per Microsoft Learn (a 1.0 is mentioned in third-party guides) — [Microsoft Learn: Agent Framework overview](https://learn.microsoft.com/agent-framework/overview/agent-framework-overview)

**LangGraph**
- A run ends when "all nodes are `inactive` and no messages are in transit", i.e. routed to `END`. The recursion limit default is 1000 steps since v1.0.6 (earlier versions defaulted to 25, per my prior knowledge) and raises `GraphRecursionError`; `RemainingSteps` allows graceful finish — [LangGraph docs: Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)
- Human-in-the-loop: `interrupt()` pauses and persists state through a required checkpointer keyed by `thread_id`; resume with `Command(resume=...)`; the node re-runs from the start, so side effects before the interrupt must be idempotent; matching on resume is index-based. Static `interrupt_before/after` are for debugging only — [LangGraph docs: interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- Lens: termination is whatever the developer's conditional edge reads. When the edge reads an LLM's "done" decision, it is self-declaration. It is the only framework here where a code-level check between agents is the natural idiom (a conditional edge).

**CrewAI**
- Processes: `Process.sequential` ("tasks are executed in the order they are defined") and `Process.hierarchical` (a manager assigns tasks by role) — [CrewAI docs: tasks](https://docs.crewai.com/en/concepts/tasks)
- Task guardrails: a function returning `(bool, Any)` or an LLM string guardrail; on failure "the error is sent back to the agent, and the task is retried up to `guardrail_max_retries` times" (default 3). `human_input` (default False) has a human review the final answer — [CrewAI docs: tasks](https://docs.crewai.com/en/concepts/tasks)
- Lens: in the default setup a task ends when its agent emits a final answer; the guardrail is the only built-in [NO-VERIFY] remedy and is opt-in.

**OpenAI Agents SDK**
- The loop ends when output is "text output with the desired type, and there are no tool calls"; `max_turns` raises `MaxTurnsExceeded` (disable with None; an error handler can return a fallback). Input guardrails raise `InputGuardrailTripwireTriggered`; output guardrails check "the agent's final response before delivery" — [OpenAI Agents SDK: running agents](https://openai.github.io/openai-agents-python/running_agents/)
- Docs warnings: input guardrails apply only to the first agent and output guardrails only to the final-output agent; tool input guardrails do not apply to handoffs. Authorisation checks belong at the start of `on_handoff`, and "the SDK continues the transfer after `on_handoff` returns successfully" — [OpenAI Agents SDK: handoffs](https://openai.github.io/openai-agents-python/handoffs/)
- Lens: intermediate agents in a handoff chain have no built-in output check [NO-VERIFY]. Completion means "no more tool calls", a self-declaration [FALSE-DONE].

**Google ADK and A2A**
- LoopAgent stops at `max_iterations` or when a sub-agent sets `escalate = True` (e.g. via an `exit_loop` tool); the docs say you "_must_ implement a termination mechanism to prevent infinite loops". As of ADK 2.0 (Python/Go), templated workflow agents are superseded by graph-based/dynamic workflows — [ADK docs: loop agents](https://adk.dev/agents/workflow-agents/loop-agents/)
- A2A task states: SUBMITTED, WORKING, INPUT_REQUIRED, AUTH_REQUIRED (interrupted), COMPLETED, FAILED, CANCELED, REJECTED (terminal). Agents are opaque by design, collaborating "without needing to share their internal thoughts, plans, or tool implementations". The spec defines states an agent reports but says nothing about verifying a COMPLETED claim [TRUST][FALSE-DONE] — [A2A specification](https://a2a-protocol.org/latest/specification/)

**Semantic Kernel agent orchestration**
- Patterns: Concurrent, Sequential, Handoff, Group Chat (coordinated by a group manager), Magentic (MagenticOne-inspired); unified invoke interface; marked experimental — [Microsoft Learn: SK agent orchestration](https://learn.microsoft.com/en-us/semantic-kernel/frameworks/agent/agent-orchestration/)

**smolagents (Hugging Face)**
- `max_steps` default 20; the agent ends by calling the final-answer tool (`step` "Returns either None if the step is not final, or the final answer"). `final_answer_checks`: "List of validation functions to run before accepting a final answer", each returning a boolean. Managed agents are called like tools; `provide_run_summary` controls whether they return a run summary. Experimental API — [smolagents API reference](https://huggingface.co/docs/smolagents/reference/agents); [ReAct guide](https://huggingface.co/docs/smolagents/conceptual_guides/react)

**Claude Code subagents**
- Subagents return a final report. If one hits `maxTurns` or an API error, the partial output is returned and marked partial/cut off. Spawn depth defaults to three layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), concurrency to 20. The final report is scanned for instruction-shaped text and markers are prepended, but "scanning is not a security boundary" — [Claude Code docs: sub-agents](https://code.claude.com/docs/en/sub-agents)
- Tool permissions in code: a `tools` allowlist (inherits all if omitted) and a `disallowedTools` denylist (a specifier like `Bash(git push *)` removes the whole tool), plus `permissionMode` (inherited and overriding when the parent is in bypass/acceptEdits/auto) — [Claude Code docs: sub-agents](https://code.claude.com/docs/en/sub-agents)

**Anthropic posts**
- "Building effective agents" (Erik S. and Barry Zhang, 19 Dec 2024): workflows ("orchestrated through predefined code paths") vs agents. Patterns: prompt chaining (with optional programmatic checks between steps), routing, parallelization (sectioning/voting), orchestrator-workers, evaluator-optimizer. It recommends stopping conditions such as "a maximum number of iterations" and getting "ground truth" from the environment at each step. It warns of "higher costs, and the potential for compounding errors", and that frameworks "obscure the underlying prompts"; "start by using LLM APIs directly" — [Anthropic](https://www.anthropic.com/engineering/building-effective-agents)
- Multi-agent research system (13 Jun 2025): the lead agent exits when it judges it has enough information, with no numeric threshold. Early agents spawned 50 subagents for simple queries and duplicated work under vague delegation. The fix was effort-scaling rules in the prompt (1 agent / 3-10 calls for simple, 2-4 subagents for comparisons, >10 for complex) — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)

**MetaGPT (as framework)**
- Hong et al., "MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework", arXiv 2308.00352 (ICLR 2024 per my prior knowledge). PDF: https://arxiv.org/pdf/2308.00352 — [arXiv](https://arxiv.org/abs/2308.00352). MetaGPT is one of the seven MAST systems — [MAST v3](https://arxiv.org/html/2503.13657v3)

**2026 framework / protocol papers adding verified termination**
- VMAO, "Verified Multi-Agent Orchestration: A Plan-Execute-Verify-Replan Framework", arXiv 2603.11445 (2026). LLM-based completeness verification and replanning; completeness 3.1 → 4.2 (1-5 scale) on 25 market-research queries vs single agent (search snippet) — [arXiv PDF](https://arxiv.org/pdf/2603.11445v2)
- TraceFix, arXiv 2605.07935 (8 May 2026). Repairs MAS coordination protocols with TLA+ model-checker counterexamples, targeting races, deadlocks, missed handshakes and premature termination; reported best paper at ACM CAIS 2026 (lab page, not venue page) — [arXiv](https://arxiv.org/abs/2605.07935); [Rutgers lab page](https://ortiz.rutgers.edu/projects/tracefix/)

### Inferences
- Classification (hard cap in code / semantic stop by agent self-report / built-in result check):
  - AutoGen: cap yes (messages, tokens, time); self-report via TextMention/StopMessage; check via FunctionalTermination (opt-in)
  - LangGraph: cap yes (recursion limit); stop is whatever the developer's edge reads; check via conditional edges/interrupts (dev-written)
  - CrewAI: cap via guardrail retries; self-report via the agent's final answer; check via task guardrail + human_input (opt-in)
  - OpenAI SDK: cap yes (max_turns); self-report via "no tool calls"; check via output guardrail on the final agent only
  - ADK: cap yes (max_iterations); self-report via escalate/exit_loop; no built-in check
  - A2A: no cap in protocol; self-report via COMPLETED state; no check
  - smolagents: cap yes (max_steps 20); self-report via final_answer tool; check via final_answer_checks (opt-in)
  - Claude Code: cap yes (maxTurns, depth 3); self-report via the final report; no check (scan is for injection, not correctness)
  - Anthropic research system: per post, the lead agent judges completion; no check stated
- In contract terms, every framework pays out (ends the episode) on the agent's report, with code caps only as a backstop. MAST's FM-1.5 + FM-3.1 (18.6%) and the false-success studies measure what that design costs.

### Gaps
- AG2 GroupChat defaults (max_round, speaker_selection_method, max_consecutive_auto_reply) could not be confirmed: the AG2 API page returned 404.
- Semantic Kernel group chat manager termination details (e.g. maximum invocation count) were not on the overview page I fetched.
- No vendor doc I read publishes measured failure rates for its own framework. The docs warn about mechanics (infinite loops, guardrail scope, idempotence), not about false completion.

## Q4. Which frameworks pass the full transcript to the next agent, and which pass a structured result?

### Takeaway
They split cleanly. The full transcript is the default in the OpenAI Agents SDK handoff ("gets to see the entire previous conversation history") and in AutoGen/AG2 group chats (a shared conversation). Shared mutable state is the default in LangGraph (one state schema) and ADK (session state via `output_key`). A summarized or structured result is the default in Claude Code subagents (the parent sees only the final report; the subagent sees only a delegation message), the Anthropic research system (condensed findings or artifact references), smolagents managed agents (a return value, optional run summary), CrewAI (the previous task's output, structured if `output_pydantic`/`output_json` is set) and A2A (Artifacts, opaque agents). Cognition argues for full traces; Tran & Kiela's DPI argument says any summary can only lose information. Anthropic counters with artifacts plus references to avoid a "game of telephone".

### Cited Findings
- OpenAI Agents SDK: by default the receiving agent "gets to see the entire previous conversation history". `input_filter` (e.g. `remove_all_tools`) can trim it; `nest_handoff_history` (opt-in beta) "compacts summarizable history into ordered assistant summary segments" and "does not redact sensitive data". `input_type` types only the handoff-call arguments. `remove_all_tools` leaves tool data already copied into messages. Server-managed conversations do not support input filters — [OpenAI Agents SDK: handoffs](https://openai.github.io/openai-agents-python/handoffs/)
- LangGraph: "Typically, all graph nodes communicate with a single schema"; a node can write any channel; the default reducer overwrites and `operator.add` accumulates. `Command(goto=..., update=...)` is "particularly useful when implementing multi-agent handoffs"; `Command.PARENT` routes from a subgraph to the parent — [LangGraph docs: Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)
- Google ADK: sub-agents communicate through session state; `output_key` writes an agent's result to a named key, which later agents read via template placeholders (Critic writes `criticism`, Refiner reads and overwrites `current_document`) — [ADK docs: loop agents](https://adk.dev/agents/workflow-agents/loop-agents/)
- CrewAI: "the output of one task is automatically relayed into the next one" in sequential mode; `context=[...]` pulls non-adjacent tasks; `TaskOutput` holds only `raw` unless `output_pydantic`/`output_json` is set — [CrewAI docs: tasks](https://docs.crewai.com/en/concepts/tasks)
- Claude Code: a subagent "doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read. Claude composes a delegation message that summarizes the task". It gets its own system prompt, the CLAUDE.md hierarchy and a git status snapshot, and "returns only the summary". The exception is a fork, which inherits the full conversation. The docs warn that verbose subagents still add to the main context when they report back — [Claude Code docs: sub-agents](https://code.claude.com/docs/en/sub-agents)
- Anthropic research system: subagents return condensed findings; for some outputs they "store results in external artifacts and pass lightweight references back", to avoid "game of telephone" losses. The lead's plan is saved to memory because context is truncated past 200,000 tokens [HANDOFF] — [Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)
- smolagents: managed agents are invoked as tools by a manager; `provide_run_summary` adds a run summary to the return; `return_full_result` returns a full `RunResult` instead of just the answer — [smolagents API reference](https://huggingface.co/docs/smolagents/reference/agents)
- A2A: results are returned as Artifacts ("Messages SHOULD NOT be used to deliver task outputs"); agents do not share internal thoughts, plans or tools — [A2A specification](https://a2a-protocol.org/latest/specification/)
- AutoGen group chats: in group chat teams the termination condition receives the messages produced since its last check, i.e. the agents share a conversation stream — [AutoGen docs: termination](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html). (That every participant sees the full shared history by default is from my prior knowledge of AutoGen group chat, not stated on the fetched page.)
- Cognition: "share full agent traces, not just individual messages" — [Cognition](https://cognition.com/blog/dont-build-multi-agents). Tran & Kiela: summaries through intermediate agents can only lose information (DPI) — [arXiv 2604.02460](https://arxiv.org/abs/2604.02460). Echoing is cut from up to 70% to 9% by structured responses, which argues for structured result formats between agents [ROLE] — [arXiv 2511.09710](https://arxiv.org/abs/2511.09710). Compaction summaries turned killed processes into "confirmed results" [HANDOFF][FALSE-DONE] — [arXiv 2607.13071](https://arxiv.org/abs/2607.13071)

### Inferences
- In information-design terms the frameworks offer two signal structures. The full transcript (OpenAI SDK, AutoGen) is maximally informative but exposes the receiver to every earlier unverified claim, which is a conformity/echoing channel. A summary or structured result (Claude Code, Anthropic research, smolagents, A2A, CrewAI with pydantic) is coarser but harder to be swayed by; its loss is the sender's choice of what to omit (MAST FM-2.4 information withholding, 0.85%).
- No framework attaches provenance or verification status to a handed-off claim (e.g. "this was checked against a tool / this is the agent's assertion"). Bronder 2026 suggests such labels may not be discounted by the receiver anyway (15/24 adoption when marked unchecked).
- The default trust model everywhere is that the receiver accepts the sender's result as true. The only code-level counterweights are opt-in validators (CrewAI guardrails, smolagents final_answer_checks, OpenAI output guardrails on the last agent).

### Gaps
- Semantic Kernel's handoff orchestration context-passing and Microsoft Agent Framework workflow message typing were not read in detail.
- Whether AG2 group chat sends the full history to every agent by default, and the effect of `send_introductions`, was not confirmed (404 on the API page).
- No empirical paper found that compares full-transcript vs structured-result handoff at equal compute within one framework. That would be the direct test of the Cognition vs Anthropic disagreement.

Papers seen only through summary pages (2602.15198 Colosseum, 2608.10646 ASCon, 2603.26845, 2601.22386) were not downloaded except 2602.15198. Docs and blog posts are URL-only.
