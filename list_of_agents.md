| Agent | Description |
|---|---|
| `research_partner` | A personal research web. Ideas, problems, questions, papers and repositories are all notes of equal standing, linked to each other the way an Obsidian vault links, and the user can walk the web from any note to everything connected to it. The user brings an idea, problem or question, finished or not, and the agent adds it as a note and links it to what is already there. For any note it can search arXiv and GitHub for papers and repositories that support it, refute it, or already solve it, add those as linked notes, and write a report answering the question. The user can question the report and ask about any source, and the agent answers from what it read. A problem met again starts from the part of the web it belongs to. |
| `ledger` | A ledger of the user's life in one place. It reads the user's inboxes, messaging apps, notifications and calendar, picks out what matters, and keeps a running account of it: messages that need a reply, dates coming up, things the user promised or was promised and that are not yet done. The user checks in with it to see what is new, what is due, and where something stands. It only reads and reports. It never replies, sends, or books on the user's behalf. |
| `examiner` | Writes the test for one agent in this lab. Pointed at a target by instructions, it reads the target's description, tools and where its state lives, clears its questions with the user, and drafts scenarios: fake starting data, the checklist the target must satisfy, and, where the target converses, the simulated user's persona and goals. The user corrects and accepts each one; accepted scenarios are saved to the shared pool. It reads the judge's results to propose the next scenarios. It never runs anything. |
| `judge` | Runs and grades scenarios from the shared pool against one agent in this lab. For each scenario it plants the fake data, starts the target as a process, plays the simulated user, verifies what the target claims against the planted data and the trace, and ticks the checklist. It runs many scenarios in parallel and stacks them to test memory and drift over time. It writes results to the pool and tells the user what passed, what broke and where. |
